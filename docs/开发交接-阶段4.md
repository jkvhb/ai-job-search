## 1. 这个项目是什么

**零第三方依赖**（Python 3.13 仅标准库 + 原生 JS 前端）的**本地** AI 求职工具：
输入一份 JD（文本/截图/链接）+ 简历 → 跑六步 SOP → 出**交互式 HTML 报告**；配套**岗位台账**、
**知识学习地图/知识库**、**面试录音 AI 复盘**、**offer 结果归因**、**简历版本库**、**真删除岗位**。
全部数据存本地。

**用户**：找 AI 领域岗位（数据标注/质检/AI 数据运营/标注管理/AI 产品经理）的求职者，中文使用者。

### ⚠️ `logs/events.jsonl` 的正确不变式是「**前缀逐字节不变、只允许追加**」

**不是**"大小不变"。这个文件是**追加型**的：用户每启动一次程序就会多出
`server.start` + 若干条 `http`。上一轮交接把它写成"30510 / 149 行不变"，
结果本轮一核对就"漂移"了 —— 一开始像是测试泄漏（本项目真出过线程活过拆解、把日志写进
真实 `events.jsonl` 的事），核对后是**良性的**：
**前 30510 字节的 sha256 逐字节一致**（`B929D8009092`），多出来的 10 行时间戳落在交接提交
之后 16 分钟 —— 是**用户自己启动了程序**。

所以核对它的正确做法是：

```powershell
python -c "import hashlib;b=open('data/profiles/default/logs/events.jsonl','rb').read();print('行数',b.count(b'\n'));print('前 30510 字节',hashlib.sha256(b[:30510]).hexdigest()[:12].upper(),'(期望 B929D8009092)')"
```

**一条命令核对全部其它基线**（只读）：

```powershell
python -c "import hashlib,os;d='data/profiles/default';exp={'jobs.json':('5875','BE673B5AE22D'),'knowledge.json':('270215','9F5A2747EBBB'),'resumes.json':('516','CFBFCB677E91'),'resumes/周汉钦-母版.md':('2455','EA5B4EB450CC')};[print(('OK  ' if (str(len(open(os.path.join(d,f),'rb').read()))==s and hashlib.sha256(open(os.path.join(d,f),'rb').read()).hexdigest()[:12].upper()==h) else 'DRIFT'),f) for f,(s,h) in exp.items()];print('files',sum(len(x) for _,_,x in os.walk('data')))"
```

**用户选的语义**：删 JD 时**连它的报告 HTML 与 JD 原文一起删**（真删除、不可恢复）。

**8 条硬要求（复核时已逐条确认）**：① 预演路由只读且逐条列清单；② 前端两步确认、
第二步逐条列文件；③ 先备份并显示路径 + 界面如实说清"语义不可恢复、但盘上留了安全备份"；
④ 删除范围（`jds.json` 记录 + 分析 + 那些报告 + JD 原文；知识库只清 `from_jds` 引用、
卡片保留；面试记录 `job_id` 清空、记录保留）；⑤ 任何一步失败 → 回滚，绝不半删；
⑥ 边界（不存在的 JD → 明确错误；无分析照样能删；缺文件如实说明）；
⑦ 原禁用按钮换成真功能；⑧ 绝不对真实数据执行删除。

**🔴 独立规格审查抓到 11 条发现，其中 2 条是能把用户数据抹掉的路（都已修）**：

| 编号 | 问题 | 修法 |
|---|---|---|
| **F1** | `store.load_jobs()` 在任何读/解析失败时返回 `[]`，而删除第 2c 步会 `save_jobs()` 把 `jobs.json` **整份覆盖**成它读到的列表 → **所有岗位的所有分析记录一次没了**，且原先不在备份里，不可回滚 | `_jobs_or_error()` 区分"文件不存在"与"读不出来"；后者让预演 `can_purge=false`、执行抛 `code=unreadable`（**宁可拒绝删，也绝不覆盖成空**） |

| F9 | 删记录用"`id` 落在集合里"当判据，本 JD 有一条没 `id` 的记录时集合里混进空串 → 删掉**所有**没 id 的记录 | 改用身份判据 `_jd_id_of_record(j) != jd_id`（与 `_analyses_of` 同口径） |
| F5 | 备份里**没有**那三份会被整份重写的 JSON → 进程被 kill 后没有任何原样副本；`rollback_failed` 的"从备份恢复"当时**做不到** | `_state/` 下按原目录结构存一份 + `manifest.json`（相对路径 + sha256 + 删的是哪个 JD） |

## 6. 诚实的缺口（已知、未修，不要当成"已完成"）

**D 相关**
- **硬 kill（进程被杀）会留下半删状态**：文件先删、JSON 后写，自动回滚只覆盖"程序自己
  捕获到的失败"。备份现在**够用**了（含三份 JSON 与面试记录 + manifest），但**恢复要人工**。
  要做成真崩溃安全得改成"先写意图日志、启动时重放" —— **没做**。
- **F1 的取舍**：台账读不出来时**整个删除功能都不可用**（不只那一个岗位）。
  刻意如此（宁可拒绝也不覆盖成空），界面也如实说了，但**没有**"只读地尽力修/隔离坏记录"的救援路径。
- **`store.load_jobs()` 在别处仍会把"读不出来"报成空**（台账渲染、查重、分析）。
  那些路径**不写文件**，所以不会丢数据，但会**显示成"台账是空的"** —— 属误导性显示，**未处理**
  （要改得动 `store` 的公共契约，面比这一轮大）。
- **真实数据仍是"迁移前"形态**（`jds.json` 不存在）：F2 / F7 那两条路径在真实数据上
  **目前够不到**（该 JD 的引用集合 == 盘上集合，8/8），只在隔离夹具上验证过。
  **跑完 `身份迁移.py` 后应再走一遍**（**要用户点头** —— 那是删除操作）。
- **真实数据上从未执行过删除**（**故意**：这个功能只能由用户自己点）。

**跨界面的老缺口**
- **"快照是在覆盖之前写的"无法用测试证明**（覆盖后用内存旧内容补写也能过所有用例）→ 只能读代码
- `app.py`（16 处）/`resumelib.py`（1 处）/`web/index.html` 注释里的 `⚠️` 不在输出路径上，**未改**（改动面最小原则）
- `merged_into` 死记录仍带 JD 级字段且**无 `jd_id`**（简历迁移给它补了 `resume_id`）→ 建议后续清理
- `app.py` 的 `_with_job_views` 是"打一次补丁 + 按线程分发"，进程内一次性替换 `store.find_job`
- 报告文件名仍是 `日期_岗位_分数.html`（不是 `<jd_id>__<简历>.html`；4A 时批准的取舍）
- 同 JD + 同简历重跑会多一份分析 + 一个 `…(2).html`
- 面试那条 `'error' != 'done'` 偶发红灯**未定位**（隔离守卫已收窄通道，但未证实修好）
- **JD 身份迁移未执行** → 指纹归一、`multi_jd` 保护对现有 6 条不生效；
  "免费播种"那一级对现有岗位不触发（`analyses_of` 只认 `jd_id`）→ 现有岗位第一次重分析会真算一次（约 206 秒），之后才进缓存
- 前端回归保护**已明显加强但仍有洞**：`tests/web_probe.py` 现在能跑真 `click()`，
  `tests/test_app.py` 里已经有一批"跑真 JS + fetch 桩"的用例；
  但**无头 Chrome E2E 仍是每轮重写、跑完删掉** → 不可复现

## 7. ⚠️ 纪律清单（**本项目最贵的资产，全是踩出来的**）

1. **还原"改坏"要备份【改后】那份，并在还原前核对 sha** —— `%TEMP%` 里可能同时有改前/改后备份，
   **用错就把未提交的实现退回去了**（本项目发生 **3 次**）
2. **绝不要用 `git checkout` / `git restore` / `git stash` 还原"改坏"**（已有实现者因此丢掉整个实现）；
   提交也**绝不 `git add -A`**（显式列文件名）
3. **变异取证要看"红在哪一行"** —— 有人把变异写成语法错，`exit=1` 红但**红在 `import` 失败**（**假红**）
4. **"加字段型"变异会被写侧净化假绿** → 变异要打在**真正落盘的那一行**
5. **断言细到"个体"，且要限定在正确的**区域** —— 绝不写"整页/整段里有没有某字符串"；
   阶段 D 又踩了两次：① 扫整段确认文案 → 被 ① 区满足；② 插错记录形状 → 触发路径根本没走到。
   **变异不红 = 测试没在测东西**，先怀疑测试
6. **别把"看起来合理"的转述当事实** —— 交接文档、实现者、审查者的转述都可能是错的：
   上一轮交接写的"缺口②（POST 成功路径没测）"**本身就是错的**（那条测试一直存在）；
   本轮独立审查给的两条数据丢失路径则是**真的**（我逐条复现过）
7. **独立审查也可能错**：它给过一条 `SPEC_GAPS` + 修法，照做会**废掉"母版留档"** → **收到意见先自己验证**
8. **测试的隔离靠"没有线程活过还原点"** —— `tests/base.py` 现有守卫（超时=响亮失败 + **故意不还原路径**）；
   全量跑前后核对真实 `events.jsonl`（**前缀 sha**，不是大小）
9. **真实数据三件套**：不修改、不删除、跑完逐项核对基线（§3）
10. **工具链坑**：`chrome.exe --version` 会**直接启动浏览器**（别跑）；
    PowerShell 的 `(Get-Content -Raw) -replace | Set-Content` 会**毁中文 + 加 BOM**（别用来改文件）；
    pwsh **不支持 `<<<`**（提交消息用 `git commit -F <文件>`）；
    `python -c` 里的 `\"` 会被 pwsh 转义搞坏（改用 here-string 走 `python -`）
11. **"读不出来"永远不等于"空/没有"** —— 阶段 D 两条数据丢失路径都是这个思维习惯造成的。
    看到 `read_json(path, default)` 这类"吞掉异常给默认值"的写法，先问一句
    "**这个默认值会被写回去吗**"
