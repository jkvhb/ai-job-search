## 1. 这个项目是什么

**【大白话】** 一个**装在你电脑上**的求职助手：把招聘网站的岗位描述（JD）粘进去，
它就自动跑一套分析流程，产出一份**网页版的分析报告**（岗位值不值得投、要会哪些东西、
简历该怎么改、面试会问什么）。另外还有：岗位清单、跨岗位积累的知识本子、面试录音复盘、
offer 结果复盘、简历版本管理、删除岗位。

**【技术口径】** **零第三方依赖**（Python 3.13 仅标准库 + 原生 JS 前端）的**本地** AI 求职工具：
输入一份 JD（文本/截图/链接）+ 简历 → 跑六步 SOP → 出**交互式 HTML 报告**；配套**岗位台账**、
**知识学习地图/知识库**、**面试录音 AI 复盘**、**offer 结果归因**、**简历版本库**、**真删除岗位**。
全部数据存本地。

**用户**：找 AI 领域岗位（数据标注/质检/AI 数据运营/标注管理/AI 产品经理）的求职者，中文使用者。

## 5. D（真删除一个 JD）—— **功能、复核、修复、文档都已完成**

**【大白话】** 这一段是"删除岗位"这个功能做完了、而且被**两个独立的检查者**（不是写代码的人）
挑过毛病。**挑出来的毛病里，有两条是真能把你的数据弄丢的** —— 这是这一节最值得看的地方。
两条的根子是同一个坏习惯：**"读不出来"被当成了"没有"**。

- **第一条**：你的岗位记录文件如果坏了（手改错 / 编码不对 / 被杀毒软件锁住），
  程序读它会得到"空的"，然后删除操作会把这个"空的"**写回去** ——
  结果**所有岗位的所有分析记录，一次性全没了**。而且它当时不在备份里，救不回来。
  → 现在改成：读不出来就**拒绝删除**，并让你先去修文件。
- **第二条**：删除失败要"回滚"（从备份把文件放回去）时，程序把"读不出来"和"本来就没有"
  混为一谈 —— 对"本来就没有"它的动作是**删掉它**。于是**一次读取失败，"回滚"就把你的岗位记录删了**。
  → 现在改成：读不出来就**碰都不碰**，并如实告诉你"这条我没把握还原"。

**提交**：`a2c9f3a`（功能，新增 `jddelete.py`；`app.py` 两个路由；前端真按钮）
→ `5d6b4d4`（复核修复）→ `a2e57c8`（文档）。

**用户选的语义**：删 JD 时**连它的报告 HTML 与 JD 原文一起删**（真删除、不可恢复）。

**8 条硬要求（复核时已逐条确认）**：① 预演路由只读且逐条列清单；② 前端两步确认、
第二步逐条列文件；③ 先备份并显示路径 + 界面如实说清"语义不可恢复、但盘上留了安全备份"；

## 7. ⚠️ 纪律清单（**本项目最贵的资产，全是踩出来的**）

**【大白话】** 这一节是"**踩过的坑，别再踩**"。每条都是真出过事才写下来的
（比如"用错备份把没提交的代码退回去了"发生过 3 次）。
第 5 条和第 11 条是最新、也是最值钱的两条：
**第 5 条**说"测试通过不等于它在测那件事"；**第 11 条**说"'读不出来'永远不等于'没有'"。

1. **还原"改坏"要备份【改后】那份，并在还原前核对 sha** —— `%TEMP%` 里可能同时有改前/改后备份，
   **用错就把未提交的实现退回去了**（本项目发生 **3 次**）
2. **绝不要用 `git checkout` / `git restore` / `git stash` 还原"改坏"**（已有实现者因此丢掉整个实现）；
   提交也**绝不 `git add -A`**（显式列文件名）
3. **变异取证要看"红在哪一行"** —— 有人把变异写成语法错，`exit=1` 红但**红在 `import` 失败**（**假红**）
4. **"加字段型"变异会被写侧净化假绿** → 变异要打在**真正落盘的那一行**
5. **断言要细到"个体"，并且必须限定在它真正声称的**作用域**里** ——
   绝不写"整页/整段里有没有某字符串"。阶段 D 一共踩了**三次**，全是作用域写错：
   ① 扫整段确认文案（被 ① 区满足）；② 插错记录形状（触发路径根本没走到）；
   ③ 扫"从 ④ 往后"（名字印到 ⑤ 也能过）。
   **变异不红 = 测试没在测东西**，先怀疑测试；但**"变异不红"也不等于测对了** ——
   每写一条断言都要问："我这句话到底约束了哪一块文本 / 哪一个对象？"
6. **别把"看起来合理"的转述当事实** —— 交接文档、实现者、审查者的转述都可能是错的：
   上一轮交接写的"缺口②（POST 成功路径没测）"**本身就是错的**（那条测试一直存在）；
   本轮独立审查给的两条数据丢失路径则是**真的**（我逐条复现过）
7. **独立审查也可能错**：它给过一条 `SPEC_GAPS` + 修法，照做会**废掉"母版留档"** → **收到意见先自己验证**
8. **测试的隔离靠"没有线程活过还原点"** —— `tests/base.py` 现有守卫（超时=响亮失败 + **故意不还原路径**）；
   **跑全量测试的前后各核对一次**真实 `events.jsonl`（**前缀 sha**，不是大小）
9. **真实数据三件套**：不修改、不删除、跑完逐项核对基线（§3）
10. **工具链坑**：`chrome.exe --version` 会**直接启动浏览器**（别跑）；
    PowerShell 的 `(Get-Content -Raw) -replace | Set-Content` 会**毁中文 + 加 BOM**（别用来改文件）；
    **本机 shell 是 PowerShell 5.1（不是 7）** —— 这解释了一串怪事，**提交消息别再用 `Out-File`**：
    `"消息" | Out-File -Encoding utf8` 会**写出 BOM**（`\xEF\xBB\xBF`），于是提交标题第一个字符
    是 U+FEFF（`git log` 里看着正常、实际脏）。**本项目已有 17 条提交中过这个招**
    （历史不改，往后干净）；`-Encoding utf8NoBOM` 在 5.1 里**不存在**（那是 pwsh 7 的）。
    **正确写法**（已验证：无 BOM + 中文正常）：
    ```powershell
    [System.IO.File]::WriteAllText($msgFile, "提交消息", (New-Object System.Text.UTF8Encoding $false))
    git commit -F $msgFile
    ```
    pwsh **不支持 `<<<`**（提交消息用 `git commit -F <文件>`）；
    `python -c` 里的 `\"` 会被 pwsh 转义搞坏（改用 here-string 走 `python -`）；
    **`git push` 报 "Could not connect to server" 而浏览器/`Invoke-WebRequest` 却正常**
    → 是**代理**问题：本机系统代理（WinINET，当前 `127.0.0.1:10808`）开着，
    但 **git 不认系统代理**（它只认 `http.proxy` 配置与环境变量）。核对手法：
    `Test-NetConnection 127.0.0.1 -Port 10808` 在听 + `git config --get http.proxy` 为空 = 就是它。
    **不要改用户的全局配置**，用一次性参数推：
    `git -c http.proxy=http://127.0.0.1:10808 -c https.proxy=http://127.0.0.1:10808 push origin main`
11. **"读不出来"永远不等于"空/没有"** —— 阶段 D 两条数据丢失路径都是这个思维习惯造成的。
    看到 `read_json(path, default)` 这类"吞掉异常给默认值"的写法，先问一句
    "**这个默认值会被写回去吗**"：会被写回去的必须**拦住**（拦住 = 拒绝执行），
    不会被写回去的只需**说清楚**
12. **多个代理共用一个工作区时，`git commit --amend` 是危险动作**（本项目真发生过，2026-10-14）：
    实现者提交后、跑变异期间，主代理在**同一个仓库**里又提交了一个 —— 实现者的 `--amend`
    把主代理那个提交**折进了自己的提交**（消息被覆盖，内容还留在树里）。
    救回来的办法：`git reset --soft <被折掉的哈希>` + 重新提交（之后主代理那个提交**哈希不变、
    内容逐字节完好**）。**两条规矩**：① 子代理**永远不许 `--amend`**；
    ② 主代理**不要在子代理干活期间往同一个仓库提交**（要提交就等它报完）。
    更彻底的做法是给每个实现者一个独立 worktree。
13. **"修复"必须配一条会红的测试** —— 本阶段三次出现"改对了但没钉住"：
    `jdid` 的读侧修复把 4 处整体退回旧写法后**全量仍全绿**。
    确认办法只有一个：**做变异**，并看清红在哪一行。加严断言（比如"原像必须逐字节存在"）
    常常是让变异变红所必需的 —— 没有它就只是"看起来测了"。
14. **测试默认都在 `default` profile 上跑**（`tests/base.py` 钉死的）——
    凡是用到路径的地方都要问一句"换个 profile 还对吗"。
    `store.profile_dir()`（无参 = `default`）与 `store.p_path()`（无参 = **当前 profile**）
    **在默认 profile 下完全一样**，这是阶段 D 那个"备份撞名、测试全绿"的成因。
    自己起的临时目录（如 `%TEMP%` 的隔离数据根）不算 —— **默认值相同 ≠ 两件事相同**
15. **文档写给人看**（2026-10-14 起）：每个技术段落先 **【大白话】** 再 **【技术口径】**；
    代码块前后必须有一句大白话；每份文档文末放术语简表并指向 `docs/术语表.md`。
    完整约定见 `specs/2026-10-14-知识库优先复用-design.md` 的《附二》
16. **变异取证/跑回归一律跑【全量】**（Task 1.10 复查踩过这个坑）——
    只跑"新测试文件"会**误判成"没被钉住"**：复查的 M6/M8 两条断言**在别的测试文件里**
    （`SnapshotByteFidelityTest` 子集全绿），**只有全量才红**。
    断言散落在哪个文件里跟"它钉住了什么"无关 —— 判据永远是
    `python -m unittest discover tests` 的**全量**结果，并且要看清**红在哪一行**。
17. **改提交消息时，别让 PowerShell 把换行吃掉**（2026-10-14 主线程自己踩的）：
    `[System.IO.File]::WriteAllText($f, $msg, …)` 里的 `$msg` 如果来自
    `git log -1 --format=%B`，在 PowerShell 里是**字符串数组**；`WriteAllText` 会把它按
    `$OFS`（默认**空格**）拼起来 → **多行正文被压成一行**（比原来的错别字更糟，而且
    `git log --oneline` 只看 subject 时**看不出来**）。
    **正确做法**：用 python 落盘（换行原样保留、还顺带无 BOM）：
    ```powershell
    $py = @'
    import subprocess, sys
    raw = subprocess.run(["git", "log", "-1", "--format=%B", "<旧提交>"],
                         capture_output=True).stdout.decode("utf-8")
    open(sys.argv[1], "wb").write(raw.replace("错别字", "对").encode("utf-8"))
    '@
    $py | python - $msgFile
    git commit --amend -F $msgFile
    ```
    改完**必须核验**：行数（`len([l for l in body.split("\n") if l.strip()])`）与"树未变"
    （`git diff --stat <原提交> HEAD` 只该是你想改的那些行）。
    ⚠️ 另注意 PowerShell 5.1 **不支持 `&&` / `||`**（整个脚本会解析失败、什么都不执行）。
    同类的坑：`python -c "…"` 里带转义引号（`[\"\x27]` 这种）会被 pwsh 解析器搞坏、
    **整条命令一个字符都不执行**（看起来像"跑了但没输出"）。**多行脚本一律 here-string + `python -`**。
18. ⚠️ **"绝不碰 `data/`"对主线程自己同样成立 —— 任何会写数据的探针必须先隔离根目录**
    （2026-10-15 主线程**真出事故**）：
    我为复现一个缺陷写了段临时探针，第一行就是 `store.save_knowledge({"nodes": []})`，
    **直接打在真实 `data/profiles/default` 上** → 用户 **145 张卡的知识库被清成 0 张**
    （509687 字节 → 19 字节）。
    **为什么测试从没出过这种事**：`tests/base.py` 的 `IsolatedCase` 会把 `store.DATA_ROOT`
    指到临时目录 —— **项目里所有测试都隔离，只有人的临时探针不隔离**。
    **铁律**：
    - 任何会写（`save_knowledge` / `absorb` / `save_resumes` / 写报告 / 迁移…）的探针，
      **第一件事**是把 `store.DATA_ROOT` 指到 `tempfile.mkdtemp()`（并同时改 `log.LOG_FILE`）；
    - **核验流程要"探针前后各打一次基线"**：只在后面打，就分不清"数据本来就长这样"
      还是"探针把它改成这样"；
    - 恢复之所以可能，是因为**复查子代理复制仓库时把 `data/` 一起带走了**，
      `%TEMP%` 里留着两份逐字节相同的 `knowledge.json`（sha12 `DD70CCE1F497`）。
      这类副本**别随手删** —— 它们是最后一道保险。
    - 证据留档约定：被我毁掉的那份存为 `knowledge.json.DAMAGED-BY-MY-PROBE-<时间戳>`，
      **不覆盖、不删除**，直到用户确认可以清掉。

## 10. 本文用到的词的简表

**【大白话】** 这里只挑本文出现、又最容易看不懂的几个。
**完整的表（几十个词）在 [`docs/术语表.md`](术语表.md)** —— 四份文档共用那一份，避免各写一套互相矛盾。

| 词 | 一句话 |
|---|---|
| **台账 / `jobs.json`** | 你每次分析的记录文件 |
| **JD 库 / `jds.json`** | 比台账多存"岗位稳定编号"和"这个岗位已算过的知识地图缓存" |
| **知识库 / `knowledge.json`** | **你跨岗位积累下来的概念本子**，一个概念一张卡 |
| **知识库优先（库优先）** | 生成知识地图时**先翻你自己的知识库**：够格的整条复用（跳过联网），不够格的照旧联网并补进那张卡 |
| **复用 / 命中 / 不够格** | 复用 = 整条用库里那份；命中 = 库里已经有这张卡（**含"不够格"与"只对齐身份"两种**，所以"命中 N 条"总是不小于"复用 M 条"）；不够格 = 缺定义 / 通俗解释 / 来源链接，仍要联网 |
| **身份对齐** | 命中后把这条的名字改成**库里的规范名**再写回（**三条支路都做**：够格 / 不够格 / 只对齐身份）—— 否则会**新建一张重复卡** |
| **只对齐身份（`aligned_only`）** | 那张卡**已经归另一条节点**了，这条只改名、内容仍是本次生成的（报告里会说"与另一条节点指向同一张卡"） |
| **`from_jds`（引用）** | 卡片里那份"这个概念从哪些岗位来的"**记账** —— 清掉它不会让卡片消失 |
| **预演 / 回滚 / 备份** | 删之前先列清单给你看 / 删失败时从备份还原 / 动手前先复制一份 |
| **逐字节 / sha256** | 一模一样到每个字节 / 一种"内容变一点，这串码就完全不同"的防伪码 |
| **profile** | 用户目录。现在只有一个（`default`） |
| **变异取证 / 假绿** | 故意改坏程序看测试红不红 / 程序坏了测试却通过 |
| **降级** | 出问题时退回"像今天一样"的做法，并如实告诉你 |
| **`file:line`** | `kb.py:372` = `kb.py` 这个文件的第 372 行 |
| **硬 kill** | 程序被强制结束（断电、任务管理器强杀） |
