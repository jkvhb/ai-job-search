## 1. 这个项目是什么

**【大白话】** 一个**装在你电脑上**的求职助手：把招聘网站的岗位描述（JD）粘进去，
它就自动跑一套分析流程，产出一份**网页版的分析报告**（岗位值不值得投、要会哪些东西、
简历该怎么改、面试会问什么）。另外还有：岗位清单、跨岗位积累的知识本子、面试录音复盘、
offer 结果复盘、简历版本管理、删除岗位。

**【技术口径】** **零第三方依赖**（Python 3.13 仅标准库 + 原生 JS 前端）的**本地** AI 求职工具：
输入一份 JD（文本/截图/链接）+ 简历 → 跑六步 SOP → 出**交互式 HTML 报告**；配套**岗位台账**、
**知识学习地图/知识库**、**面试录音 AI 复盘**、**offer 结果归因**、**简历版本库**、**真删除岗位**。
全部数据存本地。

**用户**：找 AI 领域岗位（数据标注/质检/AI 数据运营/标注管理/AI 产品经理）的求职者，中文使用者。

## 3. 真实数据的当前基线（**核对用；未经用户点头不得改动**）

> ⚠️ **先读这段，否则这张表会让你误判。**
> 这张表是**某个时刻的快照**（2026-10-14 18:0x）。**用户正常使用程序就会让它变** ——
> 跑一次分析会改 `jobs.json` / `jds.json` / `knowledge.json` / `reports/` / `data/` 文件数，
> 启动一次程序会在 `logs/events.jsonl` 追加若干行。
> 所以核对的目的是**发现"非预期的变化"**（最典型的是**测试污染**：某条用例写进了真实数据根），
> **不是**"这些数字必须一直一样"。看到数字变了，第一步是**问清楚是不是用户自己操作的**，
> 而不是当成 bug。
>
> **正确的核对方式**：
> - `logs/events.jsonl` 这种**追加型**文件：**前缀逐字节不变 + 只允许追加**
>   （`B929D8009092` 是"到 2026-10-13 21:44 为止"那一段的 sha，**永远**应该是它）。
> - 其它文件：跟这张表比，**并解释每一处差异**。
> - 最有价值的一条：**跑全量测试前后各测一次**，两次之间**不该有任何变化**
>   （这是隔离守卫的唯一有效检查）。

|---|---|---|---|
| `data/profiles/default/jobs.json` | **6264** | `4084A3A53788` | **7 条**分析（6 条迁移前形状 + 1 条带 `jd_id`），全部有 `resume_id=rv_0001` |
| `data/profiles/default/knowledge.json` | **509687** | `DD70CCE1F497` | **145 张卡**，150 条 `from_jds` 引用，**2 个来源身份** |

**【大白话】这张表和两条命令是干什么的**：这张表记的是"你的数据**在某个时刻**长什么样"
（大小 + 一串防伪码）。**它本来就会变** —— 你自己跑一次分析就会变。所以它的用途**不是**
"数字必须永远一样"，而是"**有没有人不该动却动了你的数据**"（最典型的是测试程序写进了真实目录）。
两条命令就是**自动帮你比一遍**：全打 `OK` 就没事，出现 `DRIFT` 就要查是谁改的。
**跑测试前后各跑一次这两条命令** —— 两次之间应该**完全没变化**，这是最有用的一招。

**2026-10-14 用户做过的操作（据数据推断，已核实）**：跑了至少 1 次新分析
→ 建了 1 条 JD 记录（`本科_泰盈科技集团_标注管理_多模态_成都_12-20K_0001`）、
`jds.json` 从"不存在"变成 512KB、知识库从 97 张卡涨到 145 张（新增 48 张、
5 张被两次岗位共同引用）、`jobs.json` 6 → 7 条。
**两个重要后果**：① 数据现在是**混合形态**（6 条迁移前 + 1 条迁移后），
② 我先前写的"F2/F7 两条路径在真实数据上够不到"**已不再成立**（`jds.json` 存在了）。

### 一条命令核对**追加型**文件

**【大白话】** `events.jsonl` 是"日志"，它**只会往后加行、不会改前面的**。
所以检查它的办法是"**前面那一截的防伪码没变**"（`B929D8009092` 是到 2026-10-13 21:44 为止那一段的），
而不是"整个文件大小不变"。

```powershell
python -c "import hashlib;b=open('data/profiles/default/logs/events.jsonl','rb').read();print('行数',b.count(b'\n'));print('前 30510 字节',hashlib.sha256(b[:30510]).hexdigest()[:12].upper(),'(期望 B929D8009092)')"
```

### 一条命令核对**其它**基线（只读）

```powershell
python -c "import hashlib,os;d='data/profiles/default';exp={'jobs.json':('6264','4084A3A53788'),'knowledge.json':('509687','DD70CCE1F497'),'jds.json':('512678','0D9C788DCD28'),'resumes.json':('516','CFBFCB677E91'),'resumes/周汉钦-母版.md':('2455','EA5B4EB450CC')};[print(('OK  ' if (str(len(open(os.path.join(d,f),'rb').read()))==s and hashlib.sha256(open(os.path.join(d,f),'rb').read()).hexdigest()[:12].upper()==h) else 'DRIFT'),f) for f,(s,h) in exp.items()];print('files',sum(len(x) for _,_,x in os.walk('data')))"
```

## 5. D（真删除一个 JD）—— **功能、复核、修复、文档都已完成**

**【大白话】** 这一段是"删除岗位"这个功能做完了、而且被**两个独立的检查者**（不是写代码的人）
挑过毛病。**挑出来的毛病里，有两条是真能把你的数据弄丢的** —— 这是这一节最值得看的地方。
两条的根子是同一个坏习惯：**"读不出来"被当成了"没有"**。

- **第一条**：你的岗位记录文件如果坏了（手改错 / 编码不对 / 被杀毒软件锁住），
  程序读它会得到"空的"，然后删除操作会把这个"空的"**写回去** ——
  结果**所有岗位的所有分析记录，一次性全没了**。而且它当时不在备份里，救不回来。
  → 现在改成：读不出来就**拒绝删除**，并让你先去修文件。
- **第二条**：删除失败要"回滚"（从备份把文件放回去）时，程序把"读不出来"和"本来就没有"
  混为一谈 —— 对"本来就没有"它的动作是**删掉它**。于是**一次读取失败，"回滚"就把你的岗位记录删了**。
  → 现在改成：读不出来就**碰都不碰**，并如实告诉你"这条我没把握还原"。

**提交**：`a2c9f3a`（功能，新增 `jddelete.py`；`app.py` 两个路由；前端真按钮）
→ `5d6b4d4`（复核修复）→ `a2e57c8`（文档）。

**用户选的语义**：删 JD 时**连它的报告 HTML 与 JD 原文一起删**（真删除、不可恢复）。

**8 条硬要求（复核时已逐条确认）**：① 预演路由只读且逐条列清单；② 前端两步确认、
第二步逐条列文件；③ 先备份并显示路径 + 界面如实说清"语义不可恢复、但盘上留了安全备份"；
④ 删除范围（`jds.json` 记录 + 分析 + 那些报告 + JD 原文；知识库只清 `from_jds` 引用、
卡片保留；面试记录 `job_id` 清空、记录保留）；⑤ 任何一步失败 → 回滚，绝不半删；
⑥ 边界（不存在的 JD → 明确错误；无分析照样能删；缺文件如实说明）；
⑦ 原禁用按钮换成真功能；⑧ 绝不对真实数据执行删除。

**原则的边界（值得记住）**：同样是"读不出来"，**会被这次删除整份重写的文件必须拦住**

**不会被重写的只需说清楚**（`knowledge.json` —— `kb_touched` 保持 0 就一个字都不写）。

**我自己写出的三条假绿（如实记，变异打脸后改掉）**：F9 那条插错了记录形状（真正会触发的路径
根本没走到）；二次确认"逐条"那条扫了**整段文案**（被 ① 区满足）；④ 区那条扫"从 ④ 往后"
（把名字印到 ⑤ 也能过）。**三条全是"断言写在了错的作用域上"** ——
修法都是把断言限定在它真正声称的那一小块。

## 6. 诚实的缺口（已知、未修，不要当成"已完成"）

**【大白话】** 这一节是"**已知的、还没修的问题**"，全部如实列出来。
读法：**不是"有 bug 就不能用"** —— 每一条都写了"什么情况下才会碰到"。
最值得你知道的两条：**① 程序被强制结束时，删除可能停在半路**（备份够用，但要你手工恢复）；
**② 你的数据现在一半是新格式一半是老格式**（因为那是程序自己建的，不是你手动迁移的）。

**D 相关**
- **硬 kill（进程被杀）会留下半删状态**：文件先删、JSON 后写，自动回滚只覆盖"程序自己
  捕获到的失败"。备份现在**够用**了（含三份 JSON 与面试记录 + manifest），但**恢复要人工**。
  要做成真崩溃安全得改成"先写意图日志、启动时重放" —— **没做**。
- **F1 的取舍**：台账或 JD 库读不出来时**整个删除功能都不可用**（不只那一个岗位）。
  刻意如此（宁可拒绝也不覆盖成空），界面也如实说了，但**没有**"只读地尽力修/隔离坏记录"的救援路径。
- **`store.load_jobs()` / `jdid.load_jds()` 在别处仍会把"读不出来"报成空**（台账渲染、查重、
  分析、`jdid.find_jd`）。那些路径**不写文件**，所以不会丢数据，但会**显示成"空的"** ——
  属误导性显示，**未处理**（要改得动 `store`/`jdid` 的公共"绝不抛异常"契约，面比这一轮大）。
  注意：删除路径已经不受它影响（自己做了严格读）。
- **`mtimes` 在 `try` 之外计算**（`_purge_locked`）：那里 `os.stat` 失败会逃出 `purge_jd`
  （此时还什么都没删，但会留下一个备份目录）。**未改**（审查者标 INFO）。
- **备份阶段的 `except BaseException` 会把 Ctrl+C 变成 `JdPurgeError`**（消息是准确的
  "没有删除任何东西"，但中断被吞了）。**未改**（既有模式，审查者标 INFO）。
- **数据是混合形态**（6 条迁移前分析 + 1 条带 `jd_id` 的，`jds.json` 里只有 1 条 JD 记录）：
  F2 / F7 那两条路径**现在够得到了**（`jds.json` 已存在），但只在隔离夹具上验证过 ——
  真要在真实数据上走一遍删除，**要用户点头**。
- **`身份迁移.py` 没有跑过**：`jds.json` 是**程序自己**在 2026-10-14 那次分析里建的（只有 1 条记录），

  → 现有岗位第一次重分析会真算一次（约 206 秒），之后才进缓存。
- **真实数据上从未执行过删除**（**故意**：这个功能只能由用户自己点）。

**跨界面的老缺口**

## 7. ⚠️ 纪律清单（**本项目最贵的资产，全是踩出来的**）

**【大白话】** 这一节是"**踩过的坑，别再踩**"。每条都是真出过事才写下来的
（比如"用错备份把没提交的代码退回去了"发生过 3 次）。
第 5 条和第 11 条是最新、也是最值钱的两条：
**第 5 条**说"测试通过不等于它在测那件事"；**第 11 条**说"'读不出来'永远不等于'没有'"。

1. **还原"改坏"要备份【改后】那份，并在还原前核对 sha** —— `%TEMP%` 里可能同时有改前/改后备份，
   **用错就把未提交的实现退回去了**（本项目发生 **3 次**）
2. **绝不要用 `git checkout` / `git restore` / `git stash` 还原"改坏"**（已有实现者因此丢掉整个实现）；
   提交也**绝不 `git add -A`**（显式列文件名）
3. **变异取证要看"红在哪一行"** —— 有人把变异写成语法错，`exit=1` 红但**红在 `import` 失败**（**假红**）
4. **"加字段型"变异会被写侧净化假绿** → 变异要打在**真正落盘的那一行**
5. **断言要细到"个体"，并且必须限定在它真正声称的**作用域**里** ——
   绝不写"整页/整段里有没有某字符串"。阶段 D 一共踩了**三次**，全是作用域写错：
   ① 扫整段确认文案（被 ① 区满足）；② 插错记录形状（触发路径根本没走到）；
   ③ 扫"从 ④ 往后"（名字印到 ⑤ 也能过）。
   **变异不红 = 测试没在测东西**，先怀疑测试；但**"变异不红"也不等于测对了** ——
   每写一条断言都要问："我这句话到底约束了哪一块文本 / 哪一个对象？"
6. **别把"看起来合理"的转述当事实** —— 交接文档、实现者、审查者的转述都可能是错的：
   上一轮交接写的"缺口②（POST 成功路径没测）"**本身就是错的**（那条测试一直存在）；
   本轮独立审查给的两条数据丢失路径则是**真的**（我逐条复现过）
7. **独立审查也可能错**：它给过一条 `SPEC_GAPS` + 修法，照做会**废掉"母版留档"** → **收到意见先自己验证**
8. **测试的隔离靠"没有线程活过还原点"** —— `tests/base.py` 现有守卫（超时=响亮失败 + **故意不还原路径**）；
   **跑全量测试的前后各核对一次**真实 `events.jsonl`（**前缀 sha**，不是大小）
9. **真实数据三件套**：不修改、不删除、跑完逐项核对基线（§3）
10. **工具链坑**：`chrome.exe --version` 会**直接启动浏览器**（别跑）；
    PowerShell 的 `(Get-Content -Raw) -replace | Set-Content` 会**毁中文 + 加 BOM**（别用来改文件）；
    pwsh **不支持 `<<<`**（提交消息用 `git commit -F <文件>`）；
    `python -c` 里的 `\"` 会被 pwsh 转义搞坏（改用 here-string 走 `python -`）
11. **"读不出来"永远不等于"空/没有"** —— 阶段 D 两条数据丢失路径都是这个思维习惯造成的。
    看到 `read_json(path, default)` 这类"吞掉异常给默认值"的写法，先问一句
    "**这个默认值会被写回去吗**"：会被写回去的必须**拦住**（拦住 = 拒绝执行），
    不会被写回去的只需**说清楚**
12. **测试默认都在 `default` profile 上跑**（`tests/base.py` 钉死的）——
    凡是用到路径的地方都要问一句"换个 profile 还对吗"。
    `store.profile_dir()`（无参 = `default`）与 `store.p_path()`（无参 = **当前 profile**）
    **在默认 profile 下完全一样**，这是阶段 D 那个"备份撞名、测试全绿"的成因。
    自己起的临时目录（如 `%TEMP%` 的隔离数据根）不算 —— **默认值相同 ≠ 两件事相同**
13. **文档写给人看**（2026-10-14 起）：每个技术段落先 **【大白话】** 再 **【技术口径】**；
    代码块前后必须有一句大白话；每份文档文末放术语简表并指向 `docs/术语表.md`。
    完整约定见 `specs/2026-10-14-知识库优先复用-design.md` 的《附二》
