# 知识库优先复用（报告先查本地知识库）· 设计

- 日期：2026-10-14
- 状态：待用户审阅
- 相关：`docs/superpowers/specs/2026-10-12-知识地图缓存-design.md`（4B，本设计在它之上）
- 用户原话：「每次报告的产生，优先搜索本地知识库，能查到的放进去，查不到的再联网搜索，同时如果必要，
  可以进一步扩展和完善知识库中已有的知识点。最重要的一点：知识库和简历报告互相独立，
  当删除报告时，积累下来的知识库内容会保留，其余删除」

---

## §0 一句话

生成报告的知识地图时**先查本地知识库**：查得到且**够格**的**整条复用**（跳过联网搜索与时间线生成），
查不到的才联网；联网与补算的结果**写回**知识库（新建卡片或**补全已有卡片**）。
知识库与报告互相独立 —— 删报告**不动**知识库，本设计不得破坏这一点。

## §1 用户的 7 条决策（本设计的全部依据）

| # | 决策 | 取值 |
|---|---|---|
| 1 | 「删除报告」的含义 | 用户担心的是**删报告会把知识库那份一起删掉**。现状已正确（删岗位只清 `from_jds` 引用，卡片 21 个字段一个不动）→ 本设计**必须保持**并加回归测试钉住 |
| 2 | 「能查到」的够格标准 | `definition` + `plain_explanation` + **≥1 条真实来源链接**。不够格的走联网，并**把来源补回知识库** |
| 3 | 匹配口径 | **确定性规则先走**（完全同名 / 别名 / **ASCII** 括号缩写），剩下的**交给模型判一次**；模型**只能从库里已有项里选**，不许自己造 |
| 4 | 库里缺时间线 | **补算**（模型调用，**不联网搜索**）并写回 |
| 5 | 定义归属 | **整条用库里那份**（连 `definition` / `plain_explanation` 也覆盖） |
| 6 | 复用时要不要记账 | **要**：把本次岗位记进卡片的 `from_jds`（= 「这个概念出现在哪些岗位」） |
| 7 | 实现形状 | **新模块 `kbreuse.py`**，生成流程只留**一个注入点**（用户否掉了"混进生成流程"与"做成第四级回退"两种形状） |

### 决策 5 的已知副作用（如实记）
本次为这个岗位新写的定义会被丢弃，报告里可能出现**另一个领域**（如语音评测）的措辞出现在
标注管理的报告里。缓解：报告里标注出处（§8），用户能一眼看出它不是为这个岗位量身的。

### 决策 6 的已知后果（如实记）
`from_jds` = 「这个概念**出现**在哪些岗位」，不是「哪些岗位**贡献**了内容」。
`kb._review_score` 按 `(1 + len(from_jds))` 加权（`kb.py:438`），所以**反复考的**概念会被顶到复习队列前面。
这是**刻意**的（用户要的正是这个信号）。副作用：该数字会比"真正写过内容的岗位数"大。

## §2 现状（改前，全部实测，带 `file:line`）

### 一次分析的六个调用，各自产生什么

| 步骤 | 调用 | 产生 | 复用时能否省 |
|---|---|---|---|
| ① `extract_nodes` | 1 次模型 | `id` / `term` / **`definition`** / **`plain_explanation`** / `category`（12~15 个核心） | **省不了**（不跑就不知道要哪些概念） |
| ② `brainstorm` | 1 次模型 | 扩展的关联概念 | 省不了 |
| ③ `attach_sources` | **每个知识点 1 次联网搜索** | `sources` | **能省**（额度大头） |
| ④ `attach_timeline` | **每个有来源的知识点 1 次模型** | `timeline` | 库里已有 → **能省** |
| ⑤ `kb.absorb` | 无（纯本地合并） | 写回知识库 | — |

证据：`EXTRACT_SYSTEM` 的产出字段在 `knowledge.py:144-146`，`normalize_node` 落成节点字段
`knowledge.py:162-177`；`attach_sources` 的搜索在 `knowledge.py:293`（每次 `max_results=5`）；
`attach_timeline` 只处理**有来源**的节点（`knowledge.py:321`）且用模型写（`knowledge.py:335-339`）；
编排在 `build_for_jd`（`knowledge.py:357-367`）。

### 知识地图今天**完全不读**本地知识库
- `knowledge.py` 只 import `json/re/ThreadPoolExecutor/llm/log/search/store`（`knowledge.py:3-10`），**没有** `kb`。
- 流程里唯一读 `knowledge.json` 的地方在 `kb.absorb` 内部（`kb.py:368`），而它是在
  **报告渲染之后**才调的（`render_report` `app.py:1323` 早于 `kb.absorb` `app.py:1336`）。
- `jdfacts` 按**岗位**缓存整份地图，且明确拒绝从知识库重建（`jdfacts.py:29-31`）——
  所以**两个不同岗位共享一个概念时，今天要各付一次搜索**。

### 跨岗位命中率（用用户自己的两次分析实测）

**字面相似度的错例**（这是本设计**拒绝**用它的直接证据）：

| 会被认成同一个 | 实际 |
|---|---|
| 风险识别 ↔ 语音识别 | 完全不同的两个概念 |
| 众包标注 / 标注仲裁 / 标注指南 ↔ 序列标注 | 不同 |
| 多模态大模型 ↔ 大模型幻觉 | 不是一回事 |

它也能认对（`比较平均意见得分`↔`比较平均意见分`、`语音质量感知评价`↔`语音质量感知评估`、
`词错误率与字错误率`↔`词错误率`）—— 但**认错的代价是报告里塞进另一个概念的解释且看不出来**，
所以字面相似度**不用**（§5）。

### 知识库卡片里有什么、写回时会动什么
- 21 个字段：`kb.py:238-268`（另加 `kb.py:95-107` 归一化的复习字段、`kb.py:555` 的 `last_interview_jd`）。
- 写回 = `kb.absorb` → `_merge_into`（`kb.py:271-306`）：来源**取并集**；时间线**只变长**
  （`len(new) > len(old)`，`kb.py:280`）；定义/通俗解释**只在严格更长时**覆盖（`kb.py:283-286`，
  所以等长的复用不会产生churn）；**用户进度（`state`/`last_outcome`/`asked_count`）一律不动**
  （`kb.py:274`、`302-304`）；`related`/`interview_questions` 取并集。
- 写盘前还有"损坏的知识库先改名备份、绝不当空库静默覆盖"的保护（`kb.py:309-334`）。

### 删除路径今天对知识库做了什么（决策 1 的现状证据）
- `jddelete._strip_references`（`jddelete.py:712-741`）：逐卡片把 `from_jds` 里指向该 JD 的条目去掉，
  **不删卡片、不改任何其它字段**；只在真的改动时才写盘。
- 回归测试：`tests/test_jddelete.py::test_purge_removes_records_files_and_clears_references_only`
  逐条断言"卡片还在、别的来源没被顺手删掉"。
- `from_jds` 为空是**有意义**的（界面不显示来源岗位、复习优先级降为基准），卡片依然可查可用。

## §3 数据流（改后）

```
① extract_nodes（模型）      → 12~15 个核心概念（含 definition / plain_explanation）
② brainstorm（模型）        → 扩展的关联概念
   ─────────── 新增：kbreuse.plan(nodes) ───────────
   建立索引 → 确定性匹配 → 剩下的交给模型判一次
     · 命中且够格 → 整条用库里那份（term/definition/plain_explanation/sources/timeline）
                    标 kb_reuse 出处 → **③ 一定跳过**
                    **④ 的取舍只看一件事：库里那张卡本来有没有时间线**
                      - 有 → `got="all"` → ④ 也跳过
                      - 没有 → `got="sources"` → ④ 照跑（用库里的来源补算），并写回那张卡片
     · 命中但不够格 → 记下目标卡片 → 仍走 ③④ → 写回**那张已有卡片**（不新建）
     · 没命中 → 仍走 ③④ → 写回时新建卡片（与今天相同）
   ────────────────────────────────────────────────
③ attach_sources（联网）    → 跳过所有 `kb_reuse.reusable == True` 的节点
④ attach_timeline（模型）   → 跑有来源的节点，但跳过 `kb_reuse.got == "all"` 的（时间线也来自库）
⑤ 落盘：报告（含知识地图快照）→ kb.absorb（已有的合并逻辑，**不新增写路径**）
```

**省下来的量**（可精确陈述）：
`省下的搜索次数 = reusable 为真的节点数`；
`省下的时间线模型调用 = got == "all" 的节点数`。

## §4 `kbreuse.py` 的接口

单一职责：**给一个知识点，回答"库里有吗、是哪一张、能不能直接用"；以及"该往库里补什么"。**
它**不写盘**（写盘一律走 `app.do_analyze` 里已有的 `kb.absorb`）。

```python
# 内部形状
Match = {"card_id": str, "card_term": str, "matched_by": "exact|alias|abbrev|assisted",
         "reusable": bool, "missing": [...], "got": "all|sources", "origin": {...}}

class Index:
    @classmethod
    def build(cls, nodes): ...          # nodes = knowledge.json 的 nodes
    def lookup(self, term) -> Match|None    # 确定性：同名 / 别名 / ASCII 括号缩写

def judge(nodes, index, chat=None) -> {node_term: card_id}   # 模型判定，分块
def plan(nodes, index, chat=None) -> dict                     # 就地填充 + 返回统计
```

### 唯一的注入点（`knowledge.py` 侧的用法）

```python
def build_for_jd(jd_text, cfg, core_limit=MAX_CORE, reuse=None, search=None, chat=None):
    core = extract_nodes(jd_text, cfg, chat=chat)[:core_limit]
    expanded = brainstorm(core, cfg, chat=chat)
    all_nodes = core + expanded
    if reuse is not None:
        stats = reuse.plan(all_nodes)          # 就地填充 + 打 kb_reuse 标记
    attach_sources(all_nodes, ..., search=search)   # 跳过 reusable == True 的
    attach_timeline(all_nodes, cfg, chat=chat)      # 跳过 got == "all" 的
```

- **`reuse=None`（默认）就是今天的行为**（纯联网）→ 既有调用方与既有测试**不受影响**。
  这条是刻意的：新能力默认关闭，由 `app.do_analyze` 显式打开。
- `attach_sources` / `attach_timeline` 各加一个"跳过"判定，**不改变它们的其它语义与日志**。

`plan()` 就地做三件事：
1. 给命中且够格的节点写 `node["kb_reuse"]` 并**整条填充**内容；
2. 给命中但不够格的节点写 `node["kb_reuse"] = {..., "reusable": False, "missing": [...]}`；
   **不改内容**（让 ③④ 去跑），但记下"写回目标是这张已有卡片"；
3. 返回统计：`{"matched": n, "reused": n, "enriched": n, "timeline_reused": n}` ——
   供报告标注与日志用。

`node["kb_reuse"]` 的字段（前端与测试都依赖它，**键名即契约**）：

| 键 | 含义 |
|---|---|
| `card_id` | 命中的卡片 id（= `kb.normalize_id(card["term"])`） |
| `card_term` | 库里的**规范名**（报告标题用它） |
| `term_original` | 本次 JD 里原本的写法；**与规范名相同时为空串** |
| `matched_by` | `exact` / `alias` / `abbrev` / `assisted` |
| `reusable` | **定义、通俗解释、来源链接三者齐** → `True`（**`timeline` 不参与够格判定**） |
| `missing` | 这张卡相对"完整"缺哪些，元素取自 `definition`/`plain_explanation`/`sources`/`timeline`（可空列表）。`reusable=False` 时它至少含 `sources` 或更靠前的项 |
| `got` | 实际从库里取到了什么：`all`（内容+来源+时间线）/ `sources`（内容+来源，**时间线缺**） |
| `origin` | 这张卡**最早**的 `from_jds` 条目（`job_title`/`date`），报告标注用 |

## §5 匹配规则（确定性部分的**精确**口径）

**节点侧的键**（一个节点可以有多个键）：
1. `kb.normalize_id(node["term"])`
2. 每个**ASCII**括号内容的 `kb.normalize_id`：`词错率（WER）` → `wer`、`语音端点检测（VAD）` → `vad`、
   `评测标准（Rubric）` → `rubric`。

**索引侧的键**（每张卡片）：
1. `kb.normalize_id(card["term"])`
2. 每个 `alias` 的 `kb.normalize_id`（`card["aliases"]` 目前全是空，但合并卡片会写它）
3. 每个 **ASCII**括号内容的 `kb.normalize_id`

**命中** = 节点的任一键落在索引里。

**多个节点命中同一张卡**（`extract_nodes` 与 `brainstorm` 可能产出重名的两个节点）：
**它们都复用**（都不搜）—— 确定性同名就是同一个概念，没有再搜一次的道理。
报告里可能出现两条同名词条，这与今天"模型自己重复输出一个概念"的表现一致，
**本设计不新增节点去重**（见 §13）。

### 为什么括号只认 ASCII（并且为什么这是刻意的保守）
`响应延迟（首字延迟）` 的括号里是中文**解释性补充**，而 `词错率（WER）` 的括号里是**规范缩写**。
把中文括号也当键，会让 `Case（案例）沉淀` 贡献出一个泛化的 `案例` 键，任何叫「案例」的节点都会误命中。
所以：**只把 ASCII 括号当别名**。中文同义写法由 ① 模型判定 或 ② 用户手动合并卡片（写进 `aliases`）来覆盖。

### 明确不用字面相似度
理由见 §2 的错例表。`difflib`/编辑距离之类的做法**一律不引入** ——
它认错的形态是"报告里塞进另一个概念的内容，且看不出来"，正是本项目最不能出的错。

## §6 模型判定那一步

- **输入**：① 一份**库里已有条目**的清单（`card_id` + `term`，必要时带一行 `definition` 摘要帮助区分）；
  ② 未确定性命中的节点清单（`term` + 一行 `definition` 摘要）。
- **输出契约**：`{"pairs":[{"node":"<节点的 term 原文>","card_id":"<库里已有的 id>"}]}`
  —— 键名即契约，逐条校验：
  - `card_id` **必须存在于输入清单里**，否则**丢弃该条**（绝不允许模型"发明"一个概念）；
  - `node` 必须匹配某个未命中节点的 `term`，否则丢弃；
  - **一个 `card_id` 被多条 `node` 认领时，取第一个，其余丢弃**。这条**刻意**比确定性匹配更保守：
    确定性同名是"确凿同一"，而模型说"两个**不同**名字的节点都等于同一张卡"很可能是它认错了一个 ——
    此时只信第一个，其余节点老老实实去联网（宁可多搜一次，也不把两个不同概念都套上同一段解释）。
  - `parse_json_reply` 失败 / 形状不对 → **一条都不用**（等同"没有命中"），记日志并如实说明。
- **规模守卫**：清单超过 `MAX_JUDGE_TERMS`（初值 400）时**分块**调用；分块后仍超限则
  **退回确定性匹配**（少命中，但绝不悄悄截断清单后假装判过）。
- **失败即降级**：模型不可用 / 报错 → 全部按"没命中"处理（照旧联网），记日志，
  并在报告标注里如实说"本次没能查本地知识库"。
- 判定**只做一次**（不是每个节点一次）。

## §7 复用填充与写回边界

### 填充（够格复用）
把库里那份**整条**覆盖到节点上：
`term`（取 `card_term`，原始写法存 `term_original`）、`definition`、`plain_explanation`、
`category`、`sources`、`timeline`、`interview_questions`、`state`、`confidence`；并写 `kb_reuse`。
**`node["id"]` 不动**（它是 `store.slug`，报告里的关联概念图按它连线；改它会打断 `related` 引用）。

**刻意不复制 `related`**：它的每一项是 `{id, relation}`，而那个 `id` 是**上一次分析**里节点的
`store.slug`（例如 `edit_distance` / `cer`）—— 复制到本次报告里就是**指向不存在的节点**（断链）。
本次节点的 `related` 保持模型为这个 JD 头脑风暴出来的那份（它指向的 id 都在本次报告里）。
（知识库那张卡自己的 `related` 不受影响：写回时取并集，本来就有。）

**`confidence`** 按"有没有来源"定（与 `kb._recompute_confidence` 同一条规则）：
复用到的卡有来源 → `verified`。它**只表示"有真实来源链接"，不表示"这些来源是为本岗位核验过的"**
—— 后者由 `kb_reuse` 的标注如实承担。

**`state`** 从卡片带过来（让报告快照自洽）。它**不会**影响知识库：`kb.absorb` 的
`_merge_into` 对进度字段是"缺失才补、绝不覆盖"（`kb.py:302-304`）。


### 身份对齐（这条是防重复卡的关键）
命中的节点，`term` 对齐成 `card_term`。因为写回走的是 `kb.absorb`，而它的身份键是
`kb.normalize_id(node["term"])`（`kb.py:372`）—— 若节点仍叫 `ASR` 而卡片叫 `语音识别`，
写回会**找不到卡片 → 新建一张重复的**。

**为什么选"对齐 `term`"而不是"给节点加一个 `kb_card_id` 让 `absorb` 认"**：
前者沿用库里**已有**的身份规则（同一概念 = `normalize_id(term)` 相同），不引入第二套身份机制；
后者要改 `kb.py`（被多处共用的核心 + 已测试），面更大。

**用户可见的代价（如实写进 README）**：报告里这条的标题变成**库里的规范名**，
JD 原本的写法以括注形式并排显示。好处是**模型认错时看得见**（见 §12.3）；
代价是报告里的名词与 JD 原文不完全一致。

### 一个可验证的强不变量（验收用）
够格复用（`got="all"`）写回之后，那张卡片的**唯一变化**是：
`from_jds` 多一条（本次岗位）、`last_seen` 更新。**其余字段逐字节不变。**
理由：节点内容是从这张卡原样复制的，而 `_merge_into` 对定义/通俗解释是**严格更长**才覆盖、
时间线**只变长**、来源**取并集**（`kb.py:276-286`）—— 复制品与原件等长/等集合，所以全部保持原样。
（`got="sources"` 时多一个变化：`timeline` 可能被补长。）

### 写回（一律走已有 `kb.absorb`，不新增写路径）
| 情形 | 写回目标 | 结果 |
|---|---|---|
| 够格复用 | 原来那张卡 | `from_jds` 增加本次岗位（决策 6）；内容等长**不变**；补算的时间线会写进去 |
| 命中但不够格 | **原来那张卡**（靠身份对齐） | 新搜到的来源**并进那张卡**（并集）、时间线补进去 → 就是用户说的"扩展完善已有知识点" |
| 没命中 | 新卡 | 与今天相同 |

### 绝不越界（与 `kb.py` 既有保证一致，另有测试钉住）
1. **不删任何卡片**；本设计不引入任何删除路径。
2. **不覆盖用户进度**：`state` / `last_outcome` / `asked_count` / `review_count` /
   `last_reviewed_at` / `last_result` / `last_interview_jd` 一个都不动（`_merge_into` 的既有保证）。
3. **只会变长**：定义/通俗解释严格更长才覆盖；时间线只变长；来源取并集。
4. **不新建重复卡**：身份对齐 + "只从库里已有项里选"两道保证，另有测试。

### 知识库读不出来时
`knowledge.json` 在盘上但读不出来（手改坏 / 非 UTF-8 / 被锁） →
**跳过复用**，全部照旧联网，记日志，并在报告标注里如实说明"知识库读不出来，本次没有查库"。
**不阻止分析** —— 与删除那条的分界一致：**会被覆盖的才拦住，不会被写的只需说清**
（这里 `kb.absorb` 自己有"损坏先改名备份"的保护，`kb.py:309-334`）。

### 报告顶部那行（`knowMetaLine()`，`web/report_template.html:387-408`）
保留现有三态（`computed` / `cache` / `seeded:*`），**新增复用统计**：

📚 知识地图：本次联网查了 48 个知识点；5 个复用本地知识库（来源链接未重新搜索），
   其中 2 个的时间线也是复用库里那份

- 有命中但不够格时：`另有 3 个知识点补全了来源链接，已写回知识库`
- 库读不出来时：`⚠ 本地知识库本次读不出来，没有查库（全部联网搜索）`

来源与时间线来自本地知识库（最早来自《语音/文本评测》· 2026-10-03）

数据来源：`REPORT_DATA.knowledge[i].kb_reuse`（随报告快照一起存，老报告没有这个字段 → 不渲染那行）。

### 老报告
不改、不回填（报告里是快照）。要看新标注必须**重新分析**。
`报告体检.py --刷新模板` 只换模板、不重算知识地图 → 也拿不到 `kb_reuse`（如实写进 README）。

## §9 错误处理与降级（一律"照旧联网 + 如实说"，绝不阻断分析）

| 故障 | 行为 |
|---|---|
| `knowledge.json` 不存在 | 正常（首次使用就是空库）→ 全部联网 |
| `knowledge.json` 读不出来 / 结构不对 | 跳过复用 + 日志 + 报告里如实标 ⚠ |
| 索引建立失败 | 同上 |
| 模型判定调用失败 / 返回不合法 | 等于"没命中"，全部联网 + 日志 |
| 库里条目超过分块上限 | 分块；仍超 → 退回确定性匹配 + 日志 |
| 命中且够格，但卡片的时间线为空 | 不算故障：`got="sources"`，④ 照跑补算并写回（§3） |

## §10 测试

**每个新断言都必须配一个能把它变红的变异**（本项目纪律：变异不红 = 断言没在测东西）。

1. **匹配规则纯函数**（`tests/test_kbreuse.py`）
   - 同名命中；`alias` 命中；ASCII 括号双向命中（`词错率（WER）`↔`WER`）；
   - **中文括号不建键**（`Case（案例）沉淀` 不让 `案例` 命中）—— 这条要有反例断言；
   - `normalize_id` 的既有口径（大小写/全角空格/标点）沿用，不另造一套；
   - **多个节点命中同一张卡时"都复用"**（不是只给第一个）—— 断言两个节点都拿到了卡里的内容；
   - 索引侧的 `alias` 与 ASCII 括号键**双向**生效（库里叫 `词错率（WER）`、节点叫 `WER` → 命中；
     反之亦然）。
2. **够格判定**：定义+通俗解释+≥1 来源 → `reusable=True`；缺任一项 → `reusable=False` 且 `missing` 正确。
3. **注入式流程测试**（spy 断言"真的没搜"）
   - 注入假 `search` / 假 `chat`，断言够格复用的节点：**搜索调用 0 次**、**时间线模型调用 0 次**；
   - 命中但不够格的节点：**确实搜了**，且写回目标是**原来那张卡**（卡片数不变）；
   - 库里缺时间线的命中节点：搜 0 次、时间线调用 1 次。
4. **写回安全**
   - **强不变量**（§7）：够格复用（`got="all"`）跑完一次分析 → 那张卡片**除了
     `from_jds` 多一条与 `last_seen` 更新之外，逐字节不变**（整份卡片 JSON 前后对比）；
   - 卡片带 `state=已掌握` + `review_count=3` + `last_interview_jd` → 复用并写回后**这些字段逐字节不变**；
   - 卡片的内容**不变短**（定义/通俗解释/时间线）；
   - `got="sources"`（库里缺时间线）时，断言 `timeline` **只可能变长**、且新写进去的就是本次补算那条。
5. **重复卡防护**：模型判 `ASR`↔`语音识别` → 写回后**卡片总数不变**，且没有出现 id 为 `asr` 的新卡。
6. **模型判定的输入校验**：模型返回一个**库里不存在**的 `card_id` → 该条被丢弃（不能凭空造概念）；
   返回畸形 JSON → 一条都不用，且流程照常完成。
7. **降级**：`knowledge.json` 写坏 → 分析照常完成、全是联网、报告标注里出现"读不出来"那句。
8. **报告标注**：`knowMetaLine()` 的各档文案（用真 JS 跑，`tests/web_probe.py`）；
   老快照（无 `kb_reuse`）不渲染新行。
9. **回归（决策 1）**：`test_purge_removes_records_files_and_clears_references_only` 保持绿 ——
   删岗位后卡片与内容均保留。
10. **真实数据**：跑完核对基线（§12 说明基线会随使用漂移，核对的是**前缀 sha 与文件数**）。

1. `python -m unittest discover tests` 全绿，退出码 0。
2. 上述 10 组测试全部存在，且**每条都做过分变异取证**（记录"红在哪一行"）。

6. `build_for_jd(reuse=None)` 的行为与今天**完全一致**（既有测试全绿即为证据）。
7. `README.md` 与 `docs/开发日志.md` 补上本阶段，含 §12 的诚实局限。

## §12 诚实局限（必须写进 README）

1. **命中率取决于领域相似度** —— 用户实测（语音评测 vs 标注管理，跨领域）确定性只命中
   **5/53 = 9%**；同领域反复投递会高得多。**不承诺"大部分都能复用"**。
2. **整条复用的措辞来自另一个岗位**（决策 5），报告会标出处，但那不等于为这个岗位量身的。
3. **模型判定那一步可能认错** → 报告里会塞进另一个概念的内容。缓解有两条，都在报告里看得见：
   ① 标题用库里的规范名、并括注 **JD 里原本的写法**（´风险识别´ 被认成 ´语音识别´ 时，
   报告会写成「语音识别（JD 里写作 风险识别）」，一眼就不对）；
   ② 「来源与时间线来自本地知识库（最早来自《X》·日期）」那行标明它不是本次新查的。
   **仍不承诺零误配** —— 只是让它**可见**。
4. **`from_jds` 会因复用而增长**，复习优先级随之上升（决策 6，刻意）。
5. **老报告不会获得新标注**（报告里是快照），要看得重新分析。
6. **知识库没有版本历史**：写回不可逆。缓解：只会变长/补全、且不碰进度字段
   （`kb.py` 既有保证 + §10.4 的测试）。
7. **删报告不会删知识库**（决策 1）—— 这条是**保证**，不是局限；列在这里是为了对照。

## §13 不做的（YAGNI）

- **不做**字面相似度匹配（有明确错例，§2）。
- **不做**知识库版本历史 / 回收站。
- **不做**老报告的标注回填。
- **不做**"整个岗位的知识地图都从库复用" —— `jdfacts` 已按岗位缓存整份地图，两者会打架。
- **不做** `related` 的 id 重映射（把上次分析的节点 id 映到本次报告的节点上）——
  收益小、易错；复用节点保持本次自己的 `related` 就够（§7）。
- **不做**节点去重（两个节点解析到同一张卡时都保留，§5）。
- **不改** `kb.absorb` 的合并规则（它已有的保证正是本设计要依赖的）。
- **不新增**知识库的删除/编辑入口。
- **不在**知识库 tab 加"被复用 N 次"（决策 6 已把它记进 `from_jds`，现有界面已能显示来源岗位）。
