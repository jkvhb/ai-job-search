# 知识学习地图（Knowledge Learning Map）· 设计文档

日期：2026-09-19
状态：已与用户逐节确认

---

## 1. 目标与背景

现有工具解决的是"投出去"（找岗、拆 JD、改简历、准备面试），但缺"**投出去之后的能力补课**"。

本功能的目标：拿到一份 JD 后，不只告诉你"怎么投"，还告诉你"**该学什么、怎么学**"——

1. 从 JD **深度拆解**出需要学习的知识点（领域名词、概念）
2. 每个知识点给「专业定义 + **通俗解释** + 前世今生（来龙去脉）」
3. **头脑风暴**扩展出相关知识，形成知识网络
4. **高度可视化**，便于学习理解
5. 每个知识点标**真实信息来源**，可点进原文
6. 形成**闭环**辅助面试，知识跨岗位**累积沉淀**

## 2. 核心数据模型：知识点（Knowledge Node）

每个知识点是一个节点，字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | 稳定标识（如 `rlhf`），用于关联与去重 |
| `term` | str | 术语（如「RLHF 基于人类反馈的强化学习」） |
| `definition` | str | 专业定义 |
| `plain_explanation` | str | **通俗解释**：大白话 + 一个具体例子，给领域外的人讲明白 |
| `category` | enum | 核心概念 / 扩展概念 / 前置知识 |
| `layer` | int | 0=JD 直接拆出；1/2=头脑风暴扩展层 |
| `timeline` | list | **前世今生**：`[{year, text}]` |
| `related` | list | 关联知识：`[{id, relation}]`，`relation` ∈ 前置/对比/属于/应用 |
| `sources` | list | 来源：`[{title, url, date, accessed}]` |
| `confidence` | enum | `verified`(搜索校验) / `ai-generated`(AI 生成待查证) |
| `interview_questions` | list | 面试会怎么问 |
| `state` | enum | 待学习 / 学习中 / 已掌握 |
| `last_outcome` | enum | 面试结果：答上 / 没答上 / 未面试 |

**全局知识库（跨 JD 累积）额外字段**：

| 字段 | 说明 |
|---|---|
| `from_jds` | 来源 JD 列表（哪些岗位提到过它） |
| `asked_count` | 面试被问次数 |
| `priority` | 优先级（被问过 → 下次同类 JD 优先级↑） |

> **硬性要求（用户明确强调，2026-10-08）：全局知识库必须完整保存卡片视图里的信息，`sources`（来源）尤其关键。**
> 沉淀进 `knowledge.json` 的每个节点都要带上完整的 `sources`（`title` / `url` / `date` / `accessed`）和 `timeline`，
> 知识库列表里必须能直接点进原文——不能只存术语和定义，否则来源信息会在跨 JD 合并时丢失。

## 3. 生成管线（生成 → 校验 → 引用）

```
JD
 │ ① 拆解：模型抽出核心知识点(12–15个) + 专业定义 + 通俗解释
 │ ② 头脑风暴：每个核心点扩出 2–3 个相关知识（第 1 层预生成；第 2 层点开时按需生成）
 │ ③ 搜索：对「核心 + 第 1 层」知识点用搜索 API 查真实来源（标题 + URL）
 │              **查询不做领域锚定**：就是「{术语} 是什么」——实测锚定会把术语冲掉（见下）
 │              **相关性过滤（主护栏）**：强关键词命中即留；只命中弱关键词（模型/训练/transformer…）时，
 │              若同时命中跨领域否决词（电力/变压器/voltage/electrical engineering…）则丢弃；
 │              什么都没命中 → 丢弃。宁可不给来源，也不给错来源
 │              **数量上限**：最多搜 N 次（核心概念优先），每次请求取 5 条候选，
 │              控制 Tavily 额度消耗（按请求计费，多取条数不加钱）
 │ ④ 生成 + 校验：模型基于搜索摘要写「前世今生」时间线、精修定义与通俗解释；
 │              搜不到来源的 → confidence=ai-generated，明确标「AI 整理待查证」，不给假链接
 ▼
 输出：带来源的知识网络 + 面试题关联
```

- 步骤 ①②④ 走文本模型（DeepSeek），步骤 ③ 走搜索 API（多源）。
- 搜索结果作为「④」的上下文，强制要求：时间线/定义中出现的**可验证事实**必须能追溯到某个来源；无来源的论断降级为"AI 观点"。
- **搜索两条铁律（2026-10-08 用户反馈后确立）**：
  1. **只要 AI 领域的来源**——跨领域内容"绝对不可以出现"，因为会误导学习；
  2. **不浪费搜索额度**——结果过滤 + 次数上限，坏查询本身就是浪费。
- **护栏在"过滤"，不在"查询"（2026-10-08 修正，实测数据推翻上一版）**：
  上一版曾要求查询带领域限定（`{术语} 大模型 AI`），**实测证伪**——5 个真实术语 × 2 种写法、
  共 10 次真实 Tavily 搜索，指标 =「既切题（标题/摘要字面含术语）又属本领域」的结果数：
  `{t} 是什么` 合计 **8/15**，`{t} 大模型 AI` 只有 **5/15**（「省略恢复」3→0、「抽样检验」1→0）。
  机理：查询里只要出现「大模型 AI」，Tavily 就返回**与术语无关**的泛 AI 页面
  （如「15款大模型透明度测评」）；而过滤只验领域、不验切题，这类页面会顺利通过并被标成
  「有来源」——比原来那条 Microsoft 的错更危险（伪装成可信来源）。
  引号变体与 A/B 逐条结果完全相同（引号无效）；用节点定义做消歧的策略也只有 2/9，更差。
  → **不存在好的领域锚定查询**：查询保持裸术语，`filter_relevant()` 是唯一的主护栏。
  两者关系：`build_query()` 只负责"把术语原样送去搜"，**不承担域约束**；
  `filter_relevant()` 负责"搜回来的每条结果都必须验明是 AI 领域，否则丢弃"。
- **诚实的代价**：歧义术语（如「裁决权限」「抽样检验」）**可能一个来源都留不下** →
  该节点标 `ai-generated`，报告显示「AI 整理待查证」。这是"宁可不给来源，也不给错来源"的
  **预期行为，不是 bug**。
- 复用现有 JSON 自动修复机制（模型返回坏 JSON 时自动让模型修）。

## 4. 可视化与交互

### 4.1 主视图：卡片流 + 内嵌时间线（形态 A）
- 知识点按「核心 → 扩展」排成卡片流
- 每张卡：术语 + 专业定义 + **通俗解释**（默认展开）+ 标签（核心概念/面试高频）+ 来源 + 学习状态勾选
- 点开卡片 → 「前世今生」时间线 + 相关知识 chips + 「面试会怎么问」+ 来源链接
- 学习状态「**打钩**」：学完勾选「已掌握」，**分用户记录**（存各自 profile 目录，复用现有报告状态持久化机制）

### 4.2 卡片栈 + 面包屑跳转
- 点击关联词 → **新知识卡片盖在当前卡片上**，顶部出现面包屑：`岗位 › RLHF › SFT`
- 点面包屑任意一级、或「← 返回」→ 回到对应层级
- 本质是前端导航栈（push/pop），纯 JS 实现

### 4.3 关系总览：力导向图谱（形态 B）
- 模块内「🗺 关系总览」切换按钮
- 节点=知识点、连线=关系、颜色按分类
- 可拖拽、滚轮缩放、点节点跳回对应卡片
- 手写力模拟（~100 行），零依赖、离线可用

## 5. 三阶段交付（方案二：生成-校验）

### 阶段 1 · 报告「知识学习地图」模块 + 模块化重构
- 报告新增一个「知识学习地图」模块，交付 4.1（卡片流+时间线+来源）+ 4.2（卡片栈）
- 数据存在报告 JSON 快照里（该 JD 专属）
- **顺带重构**：把 `app.py` 拆成 `app.py`(入口+路由) + `knowledge.py`(知识管线) + `search.py`(搜索) + `store.py`(数据读写)
- **数据目录改为 profile 结构**（见 §7），并做一次性迁移（现有数据迁入 `profiles/default/`）

### 阶段 2 · 力导向图谱
- 交付 4.3，作为「关系总览」切换视图

### 阶段 3 · 全局「知识库」tab + 批量建库 + 闭环
- 工具新增「🧠 知识库」tab
- **自动沉淀**：每次分析生成的知识自动合并进 `knowledge.json`（同名词合并、来源累积）
- **批量建库**：指定方向/关键词 → 一次性批量搜索+生成，预先建库
- **学习状态机** + 复习视图（按状态/分类/来源 JD 筛选、搜索）
- **面试反哺闭环**：被问过的知识点 → 下次同类 JD 优先级↑，报告里标「你之前被问过」

### 闭环全景
```
投简历 → 分析 JD → 知识地图(卡片+时间线+来源)
                        ↓ 学习
                  通俗解释 · 前世今生 · 点原文
                        ↓ 复习(知识库 tab)
                        ↓ 面试
             被问过 → 标记 → 反哺到下次同类 JD
```

## 6. 多源搜索

- `config.json` 增 `search_providers` 数组，可配多个：Tavily（默认）/ 博查 / Bing / SerpAPI 等
- 每个 provider：`{name, base_url, api_key}`
- `search.py` 按顺序尝试，**失败/超限自动换下一个**；全部失败 → 降级为 `ai-generated`（标注待查证），不中断
- 搜索请求带查询词 + 期望结果数（3–5 条），返回 `[{title, url, snippet, date}]`

## 7. 多用户 profile 隔离

### 场景
OpenClaw + 飞书群组，多人共用同一个工具（未来 MCP 场景）。需"共享工具、隔离数据"。

### 结构
```
data/profiles/
  default/               ← 本地单机默认用户
    config.json          ← 每用户自己的 API key
    resumes/  reports/
    jobs.json  knowledge.json
    jd/  logs/events.jsonl
  <飞书user_id>/         ← 每个外部用户一个目录
```

- **profile key = 外部用户标识**（如飞书 user id）；本地单机用 `default`
- Stage 1 铺好 `profiles/<key>/` 结构 + 一次性迁移
- Stage 4 时，把 key 换成飞书用户 id 即可，目录结构不改

### 待验证（Stage 4）
OpenClaw 飞书集成能否把"消息发送者 id"传到 MCP 工具调用；若不能，用兜底（Agent 把用户名作参数带上 / 按会话隔离）。

## 8. 边界与成本控制

- 核心知识点 12–15 个；第 1 层每点扩 2–3 个，第 2 层按需点开再生成（防指数发散）
- 搜索只对「核心 + 第 1 层」做深度（时间线+来源）；第 2 层只给名词与通俗解释
- 每份 JD 搜索约 40–60 次，总耗时目标 1–2 分钟
- **搜索次数上限**：`max_searches`（默认 40，可在 `config.json` 调整），超出时**核心概念优先**、其余节点不发请求；
  实测一次 53 个节点的分析约 236 秒（搜索 18s / 时间线 77s 已并行化），搜索是最容易被浪费的额度，因此加硬上限
- 批量建库：一次限一个方向 + 总量上限（默认 200 个知识点）

## 9. 错误处理

- 搜索失败/无结果 → `confidence=ai-generated`，标「AI 整理待查证」，**不给假链接**
- 未配搜索 key → 跳过搜索，整体降级为纯模型生成 + 诚实标注（不中断）
- 同名词合并 → 保留所有来源去重；`state` 取并集
- 模型返回坏 JSON → 复用现有「自动修复」机制
- 搜索 API 超时 → 单源失败换下一源；全失败降级

## 10. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 力导向图 | 手写力模拟（canvas） | 零依赖、离线可用、已用示意稿验证可行 |
| 卡片栈 | 前端导航栈 + 面包屑 | 纯 JS，简单可靠 |
| 知识库存储 | `data/profiles/<key>/knowledge.json` | 沿用 JSON 文件方案，不引入数据库 |
| 搜索 | 多 provider + 自动回退 | 用户要求多源，复用多模型可配思路 |
| 时间线 | 纯 CSS/HTML | 无需图库 |

## 12. 明确不做（YAGNI）

- 登录/密码/权限系统（多用户靠 profile 目录隔离即可，无认证）
- 共享知识池（先全隔离；真需要再加"公共池"层）
- 学习效果自测/测验
- 知识的自动复习提醒（可后续）
