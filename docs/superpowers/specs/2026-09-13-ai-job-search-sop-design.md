# AI 求职 SOP 提示词包 · 设计文档

日期：2026-09-13
状态：已与用户逐节确认

---

## 1. 目标与背景

面向 **AI 领域社招**（数据标注、AI 数据运营、标注管理、AI 产品经理等岗位），构建一套 **模型无关、可移植的求职 SOP 提示词包**，帮助用户完成：

1. 快速定位符合要求、入职概率高的岗位（预筛 + 匹配打分）
2. 结构化拆解岗位 JD
3. 依据拆解结果列出所需能力、能力缺口，产出简历撰写大纲与重点体现清单
4. 生成面试准备材料（预测题 + 答案骨架 + 反问）
5. 维护投递追踪，避免重复投递、按节奏跟进

## 2. 交付形态

**通用 SOP 提示词包**：一组 `.md` 文件，可丢进任意 Agent 环境（Claude Code / Cursor / DeepSeek Harness / 其他带工具的 agent）或纯聊天框（ChatGPT 网页版、微信 AI 等）使用。不绑定任何特定工具或模型。

### 2.1 输出规则（能力探测 + 优雅降级）

| 运行环境 | 写文件能力 | 行为 |
|---|---|---|
| Agent 环境 | 有 | 把结果落盘为结构化 `.md` 文件（报告、资产库、追踪表） |
| 纯聊天框 | 无 | 在对话中输出完整可复制的报告全文，并提示"可保存为 `xxx.md`" |

## 3. 六步流程

```
Step 0 资产库（一次性）
  ├─ 母版简历
  ├─ STAR 经历弹药库（量化结果）
  └─ 能力→证据映射表
        │
Step 1 预筛 + 打分
  ├─ 硬门槛一票否决
  └─ 匹配打分（0–100，加权），< 阈值则提醒
        │ 达标
Step 2 JD 结构化拆解（7 块）
        │
Step 3 简历大纲 + 重点清单 + 打招呼话术
        │
Step 4 面试准备（预测题 + 答案骨架 + 反问）
        │
Step 5 投递追踪（全局表，防重复投递）
```

## 4. 硬门槛（一票否决）

| 门槛 | 规则 |
|---|---|
| 学历 | 专科及以上 |
| 外包形式 | 接受**驻场外包**；**离场外包 → 拦截** |
| 薪资区间 | 6K–20K |
| 工作地点/形式 | 驻场为主（接受驻场） |
| 工作年限 | 不做硬性限制 |
| 行业硬性要求 | **不设强制门槛**；遇到 JD 有此类要求时仅标注，不拦截，留待后期明确 |

命中拦截项时，直接输出"为何不建议投 + 缺什么硬条件"，不再跑后续步骤。

## 5. 匹配打分维度（加权，0–100）

权重从高到低：

| 维度 | 权重 | 打分内容（0–10） |
|---|---|---|
| 团队/供应商管理 | 25% | 团队规模、外包/众包管理、交付与成本控制 |
| 质量体系能力 | 22% | 质检流程、准确率/一致性指标、审核机制、SOP |
| 标注生产经验 | 20% | 标注工具、规范制定、质检、清洗、交付 |
| AI 认知 | 15% | 大模型原理、RLHF/SFT 数据、评测（eval）、prompt、数据飞轮 |
| 产品/需求能力 | 10% | PRD、需求分析、竞品、数据驱动、与算法团队协作 |
| 行业经验 | 8% | 目标行业背景（看具体 JD） |

- 合计 100%。
- 阈值默认 60（可调）；低于阈值提醒"概率偏低，是否继续"，由用户决定。
- 权重为基准值，可按岗位类型微调（如 AI 产品经理岗上调"产品/需求能力""AI 认知"），后期优化。

## 6. JD 结构化拆解模板（7 块，强制输出）

1. **岗位画像**：公司 / 团队 / 级别 / 汇报线 / 薪资 / 地点
2. **Must-have（必备）**：逐条列出硬性要求
3. **Nice-to-have（加分）**：逐条列出
4. **职责 → 业务痛点反推**：每条职责背后"为何招人、想解决什么"
5. **关键词 / 术语表**：JD 高频术语（① 简历原词保留过 ATS；② 面试对齐）
6. **能力缺口（skill gap）**：JD 要求 vs 资产库现状 → ✅已具备 / ⚠️部分 / ❌缺失
7. **预测面试题**：由职责 + 关键词反推 5–8 道

## 7. 简历大纲（Step 3，输出 4 样）

1. **重点体现清单（3–5 条卖点）**：每条 = 一句结论 + 一条可验证证据（带数字）+ 对应 STAR 故事
2. **简历撰写大纲**：按 JD 权重从高到低重排经历块；相关放最前并扩写，无关删/缩；每个 JD 关键词对应一行证据
3. **BOSS 打招呼话术**：1–2 句，突出最大匹配点 + 一个数据结果
4. **Cover Letter / 自荐信**：可选，国内社招默认不写，仅给打招呼话术

## 8. 面试准备（Step 4）

- **预测面试题（5–8 道）**：重点落在团队/供应商管理、质量体系、标注生产三大高权重维度
- **答案骨架**：每题给 `STAR 骨架 + 要打出的 2–3 个关键词`，不写死全文
- **反问问题（3–5 个）**：针对该 JD 的团队 / 交付 / 质量 / 数据流设计

## 9. 投递追踪（Step 5）

全局 `投递追踪表.md`，字段：公司 / 岗位 / 链接 / 投递日期 / 状态（已投-待回复-面试中-已拒-Offer）/ 下一跟进日期 / 备注。投递前先查表防重复投递。

## 11. 边界与错误处理

- 硬门槛不达标 → 直接拦截，输出原因与缺口
- 匹配分 < 阈值 → 提醒，由用户决定是否继续
- 未建资产库 → 首次引导先建 Step 0，之后复用
- JD 链接抓不到正文（需登录/反爬）→ 回退请用户截图或粘贴文本
- 纯聊天框无写文件能力 → 输出完整可复制报告全文并提示保存文件名
