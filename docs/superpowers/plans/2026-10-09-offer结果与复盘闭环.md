# offer 结果 + 未拿到原因 + 复盘 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在岗位台账里记录结果（复用已有状态词表）+ 自己写的原因 → AI 基于「JD + 面试复盘 + 你写的原因」归因 → 生成复盘报告 → 要补的知识点手动入库。**闭环最后一步。**

**Architecture:** 新增 `outcome.py`（结果存取 + 归因 + 证据过滤；**模型可注入**，测试不真调）；`app.py` 加 3 条路由并把 `kind="outcome"` 接进已有的 `report_template_for`；新增 `web/outcome_template.html`；`index.html` 加「🏁 结果」面板与「🔍 让 AI 归因」。

**Tech Stack:** Python 3.13 **仅标准库**（`json`/`os`/`datetime`，测试 `unittest`）；原生 JS/CSS 零依赖。

**规格来源：** `docs/superpowers/specs/2026-10-09-offer结果与复盘闭环-design.md`

### 路由（3 条）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/job/result` | `{id, status, reason}` → 保存结果；`status` 非法 → **400** |
| POST | `/api/job/attribute` | `{id}` → 归因 + 生成报告；**未到终态 → 400 并说明"还没有结果"** |
| GET | `/api/job/outcome?id=` | 读回 `application`（含 `outcome_ai` 是否存在）供前端渲染 |

- **归因是同步的**（一次模型调用）→ 路由里直接调 `outcome.attribute`，
  **失败返回结构化 500**（`do_POST` 有外层 try 吗？**先读代码确认**；`do_GET` 确认过没有，必须自己兜）
- **模板选择**：`app.report_template_for(data)` 加一条 `kind == "outcome"` → `outcome_template.html`
  （**缺省仍 JD**，老报告不受影响）

### 模板 `web/outcome_template.html`

自包含、零依赖、与现有两个模板同风格。注入点同样是 `__TITLE__` / `__REPORT_DATA__`。

结构（顺序）：
1. 页头：岗位 / 公司 / 状态 / 时间
2. **你写的原因**（原样呈现，**排在最前**）—— 没有则如实说"你没有填写原因"
3. **降级说明**（仅当 `degraded_no_interview`）："本次没有面试记录，归因只基于 JD 与你写的原因"
4. AI 总评（`verdict_summary`）
5. **可能原因**：每条带 `evidence`（显著位置）、`confidence`、`controllable` 色标；
   **`reasons_all_dropped` 时如实说"模型没有给出带依据的原因，可以重试"**（不许填泛泛之谈）
6. 不可控因素（`not_controllable`）
7. **具体改进动作**（按 `area` 分组；每条带 `why`）
8. 要补的知识点（`to_study`，每个带「➕ 加入知识库」）
9. 下次怎么调（`next_time`）
10. **原始依据**（`<details>` 折叠：面试复盘要点 + JD 要点）

要求：`esc()` 转义一切模型输出；入库按钮的成功/失败/离线三态与面试复盘报告一致
（`fetch` 抛错 → 提示"未连接到工具"并禁用）；`@media print` 友好。
