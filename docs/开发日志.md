## 2026-10-08 · 阶段 2.2：列表位置记忆 + 搜索领域约束
- 类型：`功能` + `修复`
- 背景（用户反馈）：
  1. "点击最后一个知识点，跳转到卡片视图以后再回来又要重新翻到底部太麻烦了"
  2. "仅仅是查到了字段相关，但并非 AI 领域，比如『省略恢复』的来源居然有『Microsoft 的撤销回复操作』，
     非 AI 领域的知识**这是绝对不可以出现的**，而且这会**浪费大量的搜索 tavily 额度**"

### 问题 1 · 列表视图位置记忆
- `state.listScroll` 记录 `.klist` 的 `scrollTop`，`state.lastKnow` 记住最后打开的条目
- 点条目时**先存位置再切视图**（切完 DOM 就没了，顺序不能反）
- 切回列表时恢复位置；`.klist` 上用 `box.__bound` 守卫只绑一次 scroll 监听
  （**内存即时更新 + 250ms 节流落盘**——否则滚动时每秒几十次 localStorage 同步写会卡）
- 上次打开的条目加 `.last` 琥珀色高亮；无历史位置时 `scrollIntoView({block:'center'})` 兜底
- 用遍历 `[data-kopen2]` 比对 id，而不是拼接属性选择器（规避 id 含引号时的注入）
- 验证：无头 Chrome + CDP 21 项断言全过（滚到底 2875px → 点最后一条 → 切回仍是 2875px 且高亮在可视区；刷新后也恢复）

### 问题 2 · 搜索来源跑偏（根因 = 查询没有领域锚定）
- **根因**：`attach_sources` 的查询就是 `n["term"] + " 是什么"`，**没有任何领域限定**；
  且搜回来的结果**不做相关性校验**就直接当来源用。歧义术语必然跑偏。
- **实测影响面**（只读扫描用户现有 6 份报告）：最新那份 53 节点 / **159 条来源，其中 30 条（18.9%）非 AI 领域**。
  铁证：「省略恢复」→`基础：恢复和重做操作 | Microsoft Support`；
  「Transformer 架构」→`What is a Transformer?（电力变压器，plcblog.in）`；
  「裁决权限」→司法部/美国最高法院；「升级路径」→`Windows 版本升级 | Microsoft Learn`
- **修复**（三层）：
  1. `build_query()`：查询锚定领域 → `"{term} 大模型 AI"`
  2. `filter_relevant()`：结果必须命中 `DOMAIN_KEYWORDS`，否则丢弃；全被丢弃 → `ai-generated` + `sources=[]`
     （守住"无来源绝不编造"，**宁可不给来源，也不给错来源**）
  3. `max_searches`（默认 40，可配置）：核心节点 layer 0 优先，超出不发起搜索 → 直接省额度
- 关键决策：**先锚定查询（治本），再用过滤兜底（治标）**。 ~~只做过滤会把额度浪费在注定被丢的坏查询上。~~
  ⚠️ **这条决策当天即被实测推翻，见下方「修正」——最终是"查询不动、过滤做唯一护栏"。留在这里作为反面记录。**
- 踩坑 1：过滤词表**只放中文会误杀正确的英文来源**——实测 `Transformer (deep learning)`
  （en.wikipedia）因标题无中文关键词被丢 → 补 `machine learning` / `deep learning` / `transformer` /
  `neural` / `language model` 等英文词，误杀从 30 降到 26
- 踩坑 2：**纯 ASCII 短词会子串误命中**——`"ai"` 命中 `available` / `email` / `retail`；
  `"rag"` 命中 `storage` / `paragraph` → 对所有 ≤4 字母的纯 ASCII 关键词统一加词边界
  （`(?<![a-z])kw(?![a-z])`），中文字符不受影响（「AI标注」仍命中）
- 踩坑 3：补词后又发现「自然语言处理」「强化学习」**在中文下无任何关键词命中**（`nlp`/`reinforcement`
  是英文），会被误杀 → 补 `自然语言` / `强化学习` / `多模态` / `大语言模型` / `openai` / `gpt` 等
- 踩坑 4：改动让旧测试 `test_attach_sources_marks_verified` 失败——夹具来源 `title="T"` 无领域关键词，
  被新过滤丢弃。**修夹具（换成真实感的「大模型数据标注规范 / 语料标注流程」）而不是放宽断言**
- 新增「临界丢弃」审查：人工逐条复核 30 条被丢来源，确认方向正确；
  其中 6 条属"临界"（医学 Kappa 统计、软件回归测试、大数据用户画像标签）——
  它们确实**不属于 AI 领域**，按"宁缺毋滥"丢弃是对的，代价是节点降级为待查证

### ⚠️ 修正（同日）：**上面第 1 条 `build_query` 领域锚定已被实测证伪，已撤销**
（详见 `docs/superpowers/plans/2026-10-08-知识学习地图-阶段2.2.md` 的「阶段 2.2 修正（Task 2.3）」整节）
- 实测：5 个真实术语 × 2 种写法、10 次真实 Tavily 搜索，指标 =「既切题（字面含术语）又属本领域」：
  `{t} 是什么` **8/15** vs `{t} 大模型 AI` **5/15**（「省略恢复」3→0、「抽样检验」1→0）
- 机理：查询带「大模型 AI」时，Tavily 返回泛 AI 页面（「15款大模型透明度测评」），与术语无关；
  过滤**只验领域、不验切题** → 这类页面会通过过滤被标成「有来源」，**比 Microsoft 那条更危险**
- 因此 `build_query()` 改回 `"%s 是什么"`、删除 `DOMAIN_TAG`；护栏全部交给 `filter_relevant()`
- 同时把 `filter_relevant()` 升级为**强/弱关键词 + 否决词**（修 `transformer` 同名漏洞：
  电力变压器丢、`Transformer (deep learning)` 留），`max_results` 3→5（按请求计费，多拿候选纯赚）

### 新增：`报告体检.py`（零成本维护历史报告）
- 代码修好后**已生成的报告仍带旧来源**，重新分析要花钱花额度，而过滤是纯本地计算
- `python 报告体检.py` 只体检；`--fix` 清理非本领域来源；`--刷新模板` 用新模板重渲染
  （两者都会先整目录备份；`--刷新模板` 只换骨架、`REPORT_DATA` 原样保留）
- **为什么需要"刷新模板"**：报告是**快照**，模板改了旧报告不会自动更新。
  列表位置记忆这类纯前端改动要作用到已有报告，就得重新注入一次 `REPORT_DATA`——零额度成本
- `--fix` 只删判定为非本领域的来源，**绝不新增来源、绝不编造**；来源被清空的节点降级为 `ai-generated`
- 安全前置验证：最终规则下有 4 个节点（「抽样检验」「错误类型学」「裁决权限」「影响面评估」）
  会被清空全部来源，**而这 4 个节点的时间线都是 0 条**
  → 清空它们不影响全报告 130 条时间线中的任何一条，方案安全
- 用 `json.JSONDecoder().raw_decode()` 定位 REPORT_DATA，比正则可靠（JS 后续代码里也有 `}`）

## 2026-10-08 · 阶段 3.1：知识库自动沉淀 + 🧠 知识库 tab
- 类型：`功能`
- 目标：让知识不再只活在各自报告的快照里 —— 同一概念跨岗位只留一张卡，来源累加
- 新增 `kb.py`：**不调模型、不调搜索**的纯数据模块（零额度、可离线），与生成管线的 `knowledge.py` 职责分离
- 身份口径：`id = normalize_id(term)`（小写、去标点空白）→「Transformer 架构」与「transformer架构」是同一张卡
- 合并规则全部确定性且幂等：来源按 URL 去重累加、timeline 取更全、定义不用更短的覆盖、
  layer 取 min、related/面试题并集（面试题上限 8）、confidence 随来源累积重算、from_jds 按 job_id 去重
- **关键决策：用户学习进度神圣** —— `state` / `last_outcome` / `asked_count` 在任何合并中都不被覆盖。
  合并方向永远是「你的操作 → 库」，绝不「库 → 覆盖你」。有专门的回归测试钉住这条
- **关键决策：疑似重复只提示、不自动合并** —— 用户选了「精确匹配 + 提示 + 手动合并」路线。
  理由：模型自动归并要花额度，且**错并很难被发现**；启发式提示 + 人工确认既零成本又可控
- 踩坑：启发式「首尾相近」规则一开始没有长度门槛，短术语（4 字以内）极易共享首尾字，
  会产生大量假配对淹没界面 → 加「两者长度都 ≥ 6」门槛；提示区上限 20 对

## 2026-10-09 · 阶段 3.2：打钩持久化（服务端）+ 🎯 翻卡自测复习队列
- 类型：`功能` + `修复` + `决策`
- 目标：修掉用户报的「关掉程序再开，报告里的勾就没了」；顺手把知识库做成能翻卡自测的复习队列

### 根因（用户报的 bug）
- 报告里的勾选**只写 `localStorage`**（`web/report_template.html` 的 `SKEY = 'report_state:' + RID`），
  而 `localStorage` 是**按「协议 + 主机 + 端口」隔离**的 → 用 `file://` 双击打开报告、换个端口（8000→8001）、
  清一次站点数据，勾全丢
- 真正致命的是**同一件事被存了两份**：报告里 `know:` 的「已掌握」勾在浏览器，
  而知识库 tab 的掌握度（`state`）在服务端 `knowledge.json` → 所以「知识库显示已掌握、报告里却没勾」
  这种自相矛盾迟早出现。用户体感就是「知识库里的进度还在，报告的勾没了」
- 四类勾选框全在报告里：`know:`（知识点）/ `gate:`（硬门槛）/ `iq:`（面试题）/ `cl:`（重点清单）

### 关键决策
- **`know:` 的勾与知识库 `state` 统一（同一件事只存一处）**：勾上 = 已掌握，取消 = 待学习；
  「学习中」与「待学习」都渲染成未勾选（**你没说已掌握，就不给你打勾**）。
  「掌握度是用户级的」这一点让它天然只有一份真相
- 另外三类（`gate:` / `iq:` / `cl:`）存服务端 `data/profiles/<key>/report_state/<报告id>.json`（一份报告一个文件，避免单文件无限增长与写竞争）
- **身份口径复用唯一实现**：卡片 id = `kb.normalize_id(term)`，服务端做映射，前端不再写第二套归一化规则。
  核实过：真实 97 张卡的 `id` 与 `normalize_id(term)` **逐张相等** → 报告只要把**术语列表**发上去就能找回自己的卡
  （报告节点自带的模型生成 id 不参与映射）
- 知识库里没有这个概念 → **自动建卡**（把报告能提供的 definition / plain_explanation / category 一并写进去，
  不是空壳）；宁可多一张卡，也不能丢用户的勾
- 复习优先级 = `状态权重 × (1 + 被多少岗位提到) × (1 + 久未复习天数/7)`（权重 待学习3/学习中2/已掌握1，
  age 上限 30 天），**全乘性**（任何一维为 0 都不会把分数压成 0）；排序理由**显示在界面上**（黑箱排序没人信）
- 答辩推进：答上 → 直接「已掌握」；没答上 → **退一档**（已掌握→学习中→待学习，待学习留在原地）

### 诚实原则（写进实现，不只是口号）
- **失联时降级本地但明确告示**：`file://` / 工具没启动 → 顶部告示条「未连接到工具，本次打钩只存在这个浏览器里」，
  底部提示也改成真话「保存在本机浏览器」；**绝不假装存好**
- **写失败回滚勾选框**：提示「没存上，勾选已还原（未同步到工具）」
- **服务挂掉时自测不推进**：提示「未记录，请重试」，停在当前卡（实测点击后 `KB_RV.i` 不变、`busy=false`）
- 「重置我的勾选」只清本机缓存（服务端没有删除路由），**确认文案改成真话**

### 实测到的假绿（本期抓到）
- `ReviewQueueTest` 的排序断言**在权重全 1 时依然全绿**：两张卡同分，平局由术语升序决定，
  而「学习中」恰好排在「已掌握」前面 → 把权重改成全 1（等于删掉「状态权重」这一维）测试照样通过
- 补了一条**对照测试**（让「已掌握」的术语排在前面）才把这个断言钉住
  —— 教训：**排序测试里的「平局」是假绿高发区**，对照组必须让被测维度真正决定顺序

### ⚠️ 方法论陷阱（踩到、已写进计划）
- 做「把实现改坏，看测试变不变红」时，**如果改坏前后文件长度不变**（`3/2/1` → `1/1/1` 都是单字符数字），
  Python 判 `.pyc` 是否过期用的是 `(mtime, size)`：两个都没变 → **复用 `__pycache__` 里的旧字节码**，
  于是「把原文还原后测试仍然是红的」，很容易把**好测试**误判成坏的、去改一个本来正确的断言
- 判据：**还原之后仍然红，第一反应不该是「测试写错了」，而是「我读到的是不是旧字节码」**；
  改完先摸一下 mtime（或改成会变长度的写法、或跑前先 `touch` 一次）

  unittest 摘要走 stderr，在 pwsh 里不能只看管道的退出码）

### 为什么复用 vidkit，而不是自己写转写
- 本机已有 `video-link-extractor`（`vidkit`）：faster-whisper + 领域词库 + `models/medium` 都就绪，
  转写是它已经调通并实测过的能力
- 本项目**零第三方依赖**（Python 3.13 仅标准库）是硬约束：把 faster-whisper / CTranslate2 引进来 =
  几十个依赖 + 模型下载 + 打包体积，与"零依赖可分享"的定位冲突
- 走**子进程调它的 venv + 它的模块**，而不是调它的 CLI：CLI 的 `transcribe` 输出是**纯文本（时间戳全丢）**，
  我们需要**带时间戳的完整 JSON**（报告里的「原始转写全文」要正文，`duration`/`language` 要给报告表头）。
  于是 `python -c "from vidkit import transcribe; print(json.dumps(...))"`，并把 `cwd` 设成 vidkit 目录
  （让它的 `models/` 相对路径生效）
- 代价（诚实）：多了一个**外部依赖**和"用户得先有 vidkit"的门槛 → 所以配了自动探测同级目录 +
  `vidkit_dir` 配置项 + 缺失时**可操作的报错**（缺目录 / 缺 `.venv` 是两句话，用户要做的事不同）

### 给 vidkit 加 `ai` 领域，牵出 4 处遗漏
一处功能改了，**4 个地方各存了一份领域名单**没跟上：
1. 词库本身（`lexicon.DOMAINS` + `DOMAIN_PROMPTS["ai"]`）
2. CLI `--help` 的文案（领域列表写在 help 字符串里）
3. **Web 界面下拉（真功能缺口：后端已经支持 `--domain ai`，界面上根本选不到）**
4. README 里的领域说明
- 还踩到一个顺序陷阱：`ai` 必须排在 `general` **之前**。`lexicon.detect()` 判据是 `score > best_score`
  （同分时先出现的赢），而 `general` 的 signals 里本来就有"人工智能 / 算法 / 数据 / 大模型"这类泛词 ——
  `ai` 排在 `general` 后面的话，"大模型微调 + 数据标注"的讲话会以同分被判成"现代通用"，热词引导全是泛词

  真机复测明显更慢：**60 秒片段 86.3 / 116.2 / 140.8 秒（1.4～2.35×）**，同一片段 `domain='none'` 只要 21.4 秒（0.36×）
- 所以规格 §5 定的界面系数 `TRANSCRIBE_RATE = 0.9` 对"带领域词库"这条路是**偏乐观**的：
  30 分钟录音真实可能要 **40～60 分钟**，不是 27 分钟。**本轮没改**（规格钉了 0.9，且它只用于"预计"提示，
  不是承诺），但如实记在这里，交给后续决定
- 另一个观察（未改动、仅记录）：同一个 60 秒片段、同一参数，两次跑出 **15 段 / 160 字** 与 **1 段 / 71 字**
  两种结果（int8 + 多线程 + 热词的非确定性；该片段内容是八字命理，与 `ai` 提示词**不同域**）。
  domain 合适的 `daily.wav` 三次结果**完全一致** → 硬编码 `domain='ai'` 是"对 AI 面试内容最合适"的取舍，
  但不是对任何录音都合适
- 结论：**必须是后台任务 + 状态落盘**。`status()` 的判据是「文件里停在 transcribing/analyzing
  **但没有活动线程**」→ 重启后显示"上次被中断，可重试"，而不是永远转圈；
  重试见到 `transcript.json` 就跳过转写（实测：把 runner 换成"一调用就抛"的实现，重试后仍 `done`，
  `transcript.json` 的 sha256 一字未变）

### 「被问过」为什么用确定性匹配，而不是让模型判
`kb.interview_hits(text)`：知识库里每个**术语**是否出现在转写里（≥3 字出现即命中；2 字词要出现 ≥3 次，
因为"模型""标注"在口语里遍地都是）。理由：
- **可测**：一条纯函数，测试能钉住每种边界；交给模型就成了"不可测、看运气"
- **零额度**：不用为"找出被问过的词"再花一次模型调用
- **不会漏记**：模型漏读一个术语就漏记一次复习优先级，而且**没人会发现**

### 两个只有真 socket 才能发现的缺陷（计划里的沙箱测试结构上不可能发现）
1. **`rfile.read(256KB)` 在 socket 上会阻塞到凑满或对端关闭** → 上传**永远卡死**。
   计划的沙箱用例用 `BytesIO` 当 `rfile`，`BytesIO.read(256*1024)` 有多少给多少、立刻返回 ——
   阻塞这种"套接字语义"在 `BytesIO` 上根本不存在。修法：`ContentLengthReader` 按 `Content-Length`
   精确限量读、兼容 EOF，并补了**真 socket + 真 `http.client`** 的回归测试
2. **客户端中途断开被当正常结束** → **半截录音当上传成功**。`ContentLengthReader` 拿不到声明的字节数
   就返回 EOF，`save_stream` 只当正常结束。修法：`written != length` → 400「上传中断：只收到 X/Y 字节」
   + 清理半截文件。本轮验收用真 socket 复现：声明 1000 字节只发 12 字节 →
   `{"ok": false, "error": "上传中断：只收到 12/1000 字节，请重新上传"}`，目录里没有留下半截文件
- 教训：**换掉 `rfile` 的测试替你验的只是"协议之上"的逻辑**；凡是依赖"读多少、什么时候 EOF、
  对端还在不在"的行为，必须拿真 socket 验一次

### 一次真实数据误写事故与根因
- 现象：跑测试时**用户真实 data 根**被写进了面试记录/日志
- 根因：`store.DATA_ROOT` / `log.LOG_FILE` 是**模块级全局**，测试隔离靠"改全局 + `addCleanup` 还原"，
  而**后台线程的生命周期不受测试控制** —— 上传用例把 `interview.start` 换成真实现（或实现被改坏、
  漏了 413 判断继续往下走）时会**真起一条流水线线程**，它在路径还原**之后**才跑完，于是写进真实根
- 加固：凡碰上传路由的用例，**一律先调 `_no_external_calls()`**（换掉 `interview.start` 与
  `interview.ffprobe_duration`），哪怕那条路径"按理说走不到 start"
- 本轮验收遵守同一条：**只调同步的 `run_pipeline`，绝不用 `start()` 起线程**；跑完复核
  `data/` 仍是 **42 个文件**、`knowledge.json` 指纹未变、真实目录里没有 `interviews/`
- 通用教训：**"隔离"要靠"没有线程活过还原点"，不能靠"我记得还原"**

### 假绿（本轮抓到 4 次，本项目累计计数 → 9 次）
1. 计划里的 `unquote` 断言：`unquote("中文名")` **恒等** → 去掉 `unquote` 照样绿。
   改成发**真 `quote()` 编码过**的名字，并附 `assertNotIn("面试", name)` 反证才钉住
2. 计划里的 `assertIn("interviews", ...)` **太松**（路径里到处是 interviews）→ 改成断言具体文件与状态
3. 断言"页面里**没有**某句文案"——但该文案**同时也在 `<script>` 源码里**（模板的提示文案既是 DOM 文本、
   也是 JS 常量）→ **恒真**。同一个坑**出现 2 次**
- **教训：断言要读「元素状态」，不要读「整页 HTML 里有没有这个字符串」。**
  整页字符串搜索没有"存在性语义"，改哪一层都能让它变绿
- 验收阶段我自己又踩了一次**同源陷阱**（未计入上面 4 次，记在这里自省）：§12.7 的对照实验里，
  我把"被问过"的卡设成**术语升序本来就赢**的那个（「乙」<「甲」），于是删掉因子顺序不变 → 假绿；
  换成「甲」做被问过的那个才真的翻序。**排序测试里的"平局"是假绿高发区**（阶段 3.1 也栽在同一个坑）

### 一处诚实的设计取舍
岗位台账行内的「**没答上 M 个**」，**不是** `analysis.weak_concepts` 的条数（那是模型输出的条数），
而是知识库里 `last_outcome='没答上'` **且** `last_interview_jd=该岗位` 的**卡数**：
- 原因：`/api/interview/list` 只回 `status.json` 里的字段，**没有任何路由能读 `analysis.json`**
  （复盘正文走 `/reports/iv_*.html` 整页渲染，不对外暴露 JSON）
- 代价：**没建卡的术语不计入这个数**（没有卡就没有 `last_outcome`）
- 这是有意选的"**不编数字**"：宁可少报，也不把"模型建议复习 5 个词"说成"你答砸了 5 个知识点"

### 测试 + 真实数据（本轮验收）
- 真 socket 上传：200 + 真转写 + `done` + 报告落盘；超限 `413`（一个字节都不读）；

### 未做的（诚实缺口）
1. 「预计 ≈ N 分钟」用的系数 **0.9 对"带领域词库"这条路偏乐观**（真机 1.0～2.35×）—— 没改，见上文
2. `domain='ai'` 是**硬编码**的：用户不能选领域、也不能关掉词库。非 AI 录音（如语言学习、会议）会被套上
