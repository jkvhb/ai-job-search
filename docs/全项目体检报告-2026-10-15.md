## §2 P0 · 会丢数据 / 会串档（**必修**）

### P0-1 ⚠️ 知识库有一个写入口会**把整库换成空库且不留备份** ✅我验
**`kb.record_interview`（`kb.py:533`，写盘在 `:565`）**
- **证据**✅我验：隔离根里把 `knowledge.json` 写成 GBK（模拟记事本"另存为 ANSI"）→ 调 `record_interview("语音识别", …)` →
  **300 字节 → 36 字节、卡片 0、`.corrupt-*` 备份 = 0 个**。
- 可达路径：面试复盘 → `interview.py:698` → `kb.record_interview`。
- **对照**：`kb.absorb`（`kb.py:338`）**有哨兵**（先改名留档再写）✓ —— 哨兵本身是好的，只是**只接在一条路上**。
- **其余四个写入口**（`set_state`/`record_review`/`upsert_check`/`merge_nodes`）实测**拒绝写入**（数据不丢），
  但那靠的是"读到空库 → 没找到目标 → 不保存"的**副作用**，不是显式契约。
- **修法**：抽一个 `_with_kb_write(fn)`（持 `_KB_LOCK` → 先 `_quarantine_corrupt_kb()`（返回 False 就放弃并如实回报）→ `fn(kb)` → 保存），
  **五个入口全部改走它**；保留 `absorb` 的"零可吸收节点先返回"特例。
- **影响面**：照 `tests/test_kb.py:1787`（`KbAbsorbNonUtf8Test`）抄一份**参数化到 5 个入口**的坏库用例；
  `test_kb.py:1541`、`test_interview.py`、`test_app.py` 报告勾选路由。

### P0-5 ⚠️ `jobs.json` **完全没有锁** → 并发静默丢台账 ✅我验
- **证据**✅我验：隔离根里两个线程各调一次 `app._write_analysis`（即 `/api/analyze` 与结果面板的落盘路径）
  → **20 轮 ×2 条写，20/20 全部丢更新**（台账最后只剩 1 条）；并复现 `PermissionError [WinError 5]`
  从 `store.upsert_job → os.replace` **原样抛出**（线程里裸抛）。
- 结构：`jds.json` 有 `_JD_LOCK`、`knowledge.json` 有 `_KB_LOCK`、`resumes.json` 有 `_LOCK` —— **只有 `jobs.json` 没有**，
  而它的写者有四个阵营（`app._write_analysis` 无锁、`jdid.rename_jd` 持 `_JD_LOCK`、`jobdup._MERGE_LOCK`、`jddelete._JD_LOCK`）。
- 后果：报告文件还在盘上，**台账与界面上再也看不到这份分析**（那是刚花过模型 + 可能几十次搜索额度跑出来的）。
- **修法**：① `app._write_analysis`（`app.py:355-364`）整段读改写放进 `jdid._JD_LOCK`（RLock 可重入，锁序 `_JD_LOCK → _KB_LOCK` 不变）；
  ② **根因修复在 `store.py`**：`upsert_job`/`save_jobs` 加模块级 RLock，让四方共用 —— 只在 app 包一层等于没修。
- **影响面**：`tests/test_app.py:903/1312`、`tests/test_analyze_knowledge_cache.py`、`tests/test_jdid.py:742-779`、
  `tests/test_jdfacts.py:960`（后两个是**锁顺序/可重入的 AST 断言**，必须全跑确认无死锁）；**新增**一条并发用例。

## §4 P2 · 安全（本地服务的暴露面 + XSS）

### P2-1 🔴 本地服务**零来源校验** → 你随便打开的一个网页就能把你的 API Key 送出去 【读码】
- 事实：服务端全文**只读 5 个请求头**（`Content-Length`/`X-Job-Id`/`X-File-Name`/`X-Kind`），
  **没有 `Origin`、没有 `Host`、没有 `Content-Type`、没有 `Cookie` 校验**，而 `_json_body` 根本不看 Content-Type。
- 攻击：任何你浏览的页面都能对 `http://127.0.0.1:8000/api/config` 发**简单请求**（`text/plain` 不触发预检）
  → body `{"text_model":{"base_url":"https://attacker/v1"}}` → `cfg[k].update(body[k])`
  **保留你原来的 `api_key`、只换 `base_url`** → 下一次分析把 key 打到攻击者地址。**不需要读回包**。
- 同一手法：`/api/logs/clear`（销掉取证线索）、`/api/resumes`（写简历版本）、`/api/report_state/write`、`/api/demo`。
- 更远一步（**DNS rebinding**，因为没有 Host 校验）：`GET /api/config` **明文回 `api_key`**，
  加上 `/api/resumes?name=`、`/api/jd_text`、`/api/knowledge`、`/api/logs/download`、`/reports/*`、`/jd/*` ⇒ **读写全开**。
- **修法（约 12 行）**：`Host` 必须是 `127.0.0.1:<port>`（挡 rebinding）+ 若带 `Origin` 则必须同源（挡 CSRF）；
  顺手给响应加 `X-Content-Type-Options: nosniff`。
  ⚠️ **不要**把"必须 `Content-Type: application/json`"当唯一判据（`tests/test_kb.py:1207` 的沙箱 handler 不设这个头）。
- **影响面**：现有测试都不带 `Origin` ⇒ 预期**零改动**；新增"带 `Origin: https://evil` 被拒 / 不带 Origin 正常 / `Host` 非本机被拒"。

### P2-2 🔴 XSS：`href` 直接吃外部字符串（含**模型/搜索返回的 URL**）【实跑·前端路】
- `web/report_template.html:662`（`sources[].url` ← 模型/搜索输出）、`:364`（`source_link`）、`web/index.html:742`（台账原岗位链接）。
- **证据**【实跑】：`source_link = javascript:alert(1)` → 渲染出来就是 `href="javascript:alert(1)"`。
- `esc()` 只转 `&<>"'`、**不碰冒号**；`index.html:2715` 早就写好了 `kbSafeUrl()` 白名单（注释里明说"esc 不转义冒号"），
  但**只用在两处 KB 链接上**，报告模板里**根本没有这个函数**。
- **修法**：`kbSafeUrl` 提成共用 `safeUrl()`，三处都用；非 http(s) 一律渲染成纯文本。
- **影响面**：三处**零覆盖**；新增探针断言（`javascript:`/`data:` 不出现在 `href="` 里）。
  ⚠️ 改 `report_template.html` 时别把 `test_app.py:180` 断言的那个 `/api/report_state` 标记删了。

### P2-3 🟠 `target="_blank"` 缺 `rel="noopener"`（报告模板两处）【读码】一行。
