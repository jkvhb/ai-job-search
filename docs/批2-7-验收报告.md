## 三、当前的诚实缺口（随进度滚动）

1. **P1-6 只做了后端半边**（`log.read_logs` 会带出 `error`，但 `app.py` 的 `/api/logs` 与前端还没用上）⇒ 已派给批5c ✓；
2. `打包分享` 的泄漏扫描阈值是**防误伤优先**（中文 ≥2 字 / ASCII ≥3 且含字母），
   所以"恰好等于通用词（`简历`/`new`）的真名"会漏检 —— 已知取舍，写在它的汇报里；
3. `store.build_log_bundle` 在 `LOG_FILE == ""` 时 `os.path.dirname("")` 会崩（HEAD 起就有）—— 未修，属批 5 剩余；
4. README 的脚本表仍缺 `jdid.py`/`jdfacts.py`/`jobdup.py`/`jddelete.py`/`kbreuse.py`（批5b 按边界只补了报告点名的两个）；

## 四、过程纪律（本批新立，见复盘文档）

- **5.2b**：提交消息一律用 `write` 工具写成文件（本项目因在 pwsh 里用 python 字面量写消息而失败 **3 次**）；
- **4.7**：**不要在实现者还在变异时验证它的文件**（本项目真实踩到：读到的源码与跑出来的行为矛盾 ⇒ 结论无效）；
- **4.8**：探针起的**长驻进程**必须放进 `try/finally`（主线程自己的探针崩在判据行 ⇒ 服务进程留了 20 分钟、占端口）；
- **5.1 案例二 / 5.4b**：派活前**列一张在飞文件集合表交叉核对**；子代理会**静默死亡**，续接先看 mtime 与状态；
- ⚠️ **别让多个实现者同时跑全量**（实测三方同时 `discover tests` **会死锁**）。
