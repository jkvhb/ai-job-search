# AI 求职助手（本地工具 + SOP 提示词包）

> **第一次用？** 直接看 [`新手引导.md`](新手引导.md) —— 30 秒版：装 Python、填哪个 Key、三步开始。
> 本 README 是完整说明，可以当手册查。

面向 **AI 领域社招**（数据标注、AI 数据运营、标注管理、AI 产品经理等）的求职工具：
**粘贴 JD / 上传截图 → 自动跑 SOP → 生成一份交互式 HTML 分析报告**，并把简历与报告都存在本机。

> **看不懂里面的词？** 查 [`docs/术语表.md`](docs/术语表.md) —— 那里把"profile""sha256""变异取证"
> 之类的词都用日常话解释了一遍。
>
> **本 README 的写法**：讲功能的地方都是大白话；涉及程序内部机制的段落，
> 会先写 **【大白话】**（这是什么、不这么做会出什么事），再写精确说法。**你只需读【大白话】。**

## 它能做什么

1. 岗位预筛（硬门槛一票否决）
2. 岗位匹配打分（0–100，权重可调）
3. JD 结构化拆解 + 能力缺口识别
4. 简历撰写大纲 + 重点体现清单 + BOSS 打招呼话术
5. **简历优化方向**（增 / 删 / 改 / 量化补强 / 关键词对齐 / 逐段改写要点）
6. 面试准备（预测题 + 答案骨架 + 反问）
7. 投递 Checklist + 投递状态追踪
8. **知识学习地图**（JD → 核心知识点 + 通俗解释 + 前世今生时间线 + 真实来源链接，可钻取关联概念）
9. **面试复盘**（真实录音 / 视频 / 文字稿 → 本机 vidkit 转写 → AI 复盘报告 → 反哺知识库）
10. **🏁 结果与复盘**（记录拿到没拿到 offer + 你写的原因 → 到终态后让 AI 归因 → 复盘报告，闭环收口）

## 快速开始（本地工具，推荐）

1. **双击桌面上的「AI求职助手」图标**（快捷方式已放好，指向 `启动.bat`）
   - 也可以直接双击本目录的 `启动.bat`，或命令行 `python app.py`
2. 浏览器自动打开 **http://127.0.0.1:8000**
3. 首次使用：进「⚙️ 设置」填两个 API Key（模型名已内置正确值，通常不用改）
   - 文本分析：`deepseek-flash`（DeepSeek）
   - 识图 OCR：`kimi-k2.6`（Kimi / Moonshot）
   - （可选）「搜索源」：填 `tavily` 或 `bocha` 的 Key，知识学习地图才会带真实来源链接
4. 回到「① 分析岗位」：粘贴 JD / 上传截图 / 填分享链接 → 选简历 → 点「🚀 开始分析」
5. 报告存到 `data/profiles/<当前用户>/reports/`，岗位信息自动写入同目录的 `jobs.json` 台账

> **注意**：同时只能开一个窗口。重复启动会提示「端口已被占用」。

> **没有 API Key 也想先看效果？** 点「看看示例效果（免 API Key）」即可生成一份内置示例报告。

## 输出形式（交互式 HTML）

文件命名：`data/profiles/<当前用户>/reports/YYYYMMDD_岗位名_匹配分分.html`

固定 **8 个模块**：★ 岗位信息与联系方式 / 硬门槛判定 / 匹配打分 / JD 拆解·能力缺口 / 简历大纲 / **简历优化方向** / 面试准备 / **📚 知识学习地图**

顶部有**可点击目录**（吸顶、滚动高亮），点章节名直接跳转；每个模块有独立主题色。

内置 **5 项交互**：
- ✅ 勾选清单（硬门槛确认、投递 Checklist、面试题"已准备"）
- 📂 可折叠答案（点开才显示面试答案骨架）
- 🎚️ 打分滑块（拖动即实时重算总分）
- 📊 投递状态可编辑（状态 + 下一跟进日期 + 备注）
- 📤 导出 PDF（一键打印）

打分的滑块与投递状态存在本机浏览器（localStorage）；**四类勾选框存在工具里（关掉程序也不丢）**——见下面「✅ 打钩会存住」。
报告文件本身永久保存在 `data/profiles/<当前用户>/reports/`。

## ✅ 打钩会存住（关程序不丢）

以前报告里的勾选**只存在浏览器里**（`localStorage`），而浏览器存储是按「**协议 + 主机 + 端口**」隔离的：
用 `file://` 双击打开报告、换个端口访问、或者清一次站点数据，勾就全没了。
同时**同一件事被存在了两个地方**（报告里的「已掌握」勾在浏览器、知识库里的掌握度在工具里），
于是「知识库显示已掌握、报告里却没勾」这种自相矛盾的状态迟早会出现。

现在四类勾选框分两种存法：

| 勾选框 | 存在哪 | 口径 |
|---|---|---|
| `know:` 知识点「已掌握」 | **知识库那张卡的 `state`** | 与知识库 tab 的三档掌握度**是同一件事、同一处存储** |
| `gate:` 硬门槛 / `iq:` 面试题 / `cl:` 重点清单 | 工具里 `data/profiles/<当前用户>/report_state/<报告id>.json` | 每份报告一个文件 |

**`know:` 的勾就是知识库的「已掌握」**，不是两份数据：报告里勾上 = 知识库那张卡变「已掌握」；
在知识库 tab 标「学习中」= 报告里不勾（**诚实：没说已掌握**）。反过来也一样。

- ✅ **关掉程序、重开、再打开报告，勾还在**（存在硬盘上的文件里，不在内存里）
- ⚠️ **失联时降级本地，并且明确告诉你**：用 `file://` 打开报告、或工具没启动时，
  页面顶部出现告示条「**未连接到工具，本次打钩只存在这个浏览器里**」，勾选降级存本机浏览器、仍然能用
  （代价是换台机器/清缓存就没了）。**不假装存好了**
- ⚠️ **写失败会回滚勾选框**：提示「没存上，勾选已还原（未同步到工具）」，绝不显示成已保存
- ✅ 勾一个知识库里还没有的概念 → **自动建卡**（顺手把报告里的定义一起写进去，不是空壳），勾不丢

> **两个如实的说明（不是 bug，但要知道）：**
> 1. 「重置我的勾选」按钮**只清本机浏览器缓存**；工具里已经存住的勾选得用勾选框逐个取消
>    （界面上也是这么写的，不骗人）。
> 2. **已经生成的老报告页面上跑的还是老代码**（勾只落浏览器）。想让它也用上服务端持久化，
>    执行一次 `python 报告体检.py --刷新模板`（只换页面骨架，**分析结果一个字都不动**、不消耗任何额度）；
>    老的浏览器勾选**不会自动迁移**，刷新后它会照常显示，但你**手动动一下它**才会同步到工具里。

## 🧠 知识学习地图

分析岗位时会顺手把这份 JD 背后的**知识点**挖出来，作为报告的第 8 个模块：

1. **拆解核心知识点**：12–15 个该岗位真正会考的概念，每个都给「专业定义」+ **通俗解释**（大白话 + 具体例子，外行也能听懂）
2. **头脑风暴扩展**：自动补一层关联知识（前置 / 对比 / 属于 / 应用），点关联概念可继续往里钻
3. **前世今生时间线**：这个概念怎么来的、后来怎么演变的（按时间正序）
4. **真实来源链接**：每个知识点附**可点击的原文链接**（需要先配搜索源）
5. **面试会怎么问**：预测面试官的问法，边看边勾「已掌握」

报告里有**三种看法**，右上角随时切换，互不影响：

- **卡片视图**：卡片流 + 卡片栈钻取，点关联概念进入下一张卡片，顶部面包屑逐层退回
- **列表视图**：一级核心概念 / 二级扩展知识分组罗列，点任意一条直接跳进它的卡片
  （**会记住你滚到哪儿**，回来时位置和上次打开的那条都还在，不用重新翻到底部）
- **图谱视图**：力导向关系总览，拖动节点看关联，点节点进卡片

勾选状态存在工具里（见上面「✅ 打钩会存住」），来回钻取、关掉程序重开都不会丢。

> **不编造**：没找到来源的知识点会明确标「**AI 整理待查证**」，并且**不生成时间线、不给链接**——
> 宁可少写，也不编。
>
> **只要本领域的来源**：搜索查询**不加领域词**（就是「术语 是什么」）——实测发现，
> 查询里一旦带上「大模型 AI」，搜出来的反而是「15款大模型透明度测评」这类**跟术语无关**的
> 泛 AI 页面，更难看穿。所以护栏放在**搜回来之后**：对结果做领域校验，
> **非 AI 领域的内容直接丢弃**；只命中通用词（模型 / 训练 / transformer…）的结果，
> 若同时带跨领域信号（电力 / 变压器 / voltage…）也丢弃（宁可标「待查证」，也不给一条会误导你的链接）。
> 比如「省略恢复」曾经搜到「Microsoft 的撤销恢复操作」、「Transformer 架构」搜到「电力变压器」——
> 这类结果现在会被拦掉。搜索次数也有上限（默认 40 次/岗位，核心概念优先），不浪费搜索额度。
>
> **歧义术语（如「裁决权限」「抽样检验」）可能一个来源都留不下 → 该知识点会标「AI 整理待查证」。**
> 这是「宁可不给来源，也不给错来源」的**预期行为，不是 bug**。

### 搜索源需要自行配置

「⚙️ 设置 → 搜索源」里可以增删多个搜索源，支持 `tavily` / `bocha`
（按顺序尝试，一个失败自动换下一个；全失败则降级为无来源）。

**不配置也能用**，只是知识点的来源会**全部标成「AI 整理待查证」**。

### 报告维护（不重新分析、不消耗搜索额度）

报告是**快照**：分析完那一刻的内容就固定了。所以"清理跑偏来源"和"用上新版模板"都需要单独做一次，
但这两件事都是**纯本地计算**，不花钱、不耗搜索额度，改之前会自动整目录备份。

```bash
python 报告体检.py             # 只体检：列出每份报告的非本领域来源（不改任何文件）
python 报告体检.py --fix       # 清理非本领域来源
python 报告体检.py --刷新模板    # 用当前版本的报告模板重渲染（数据原样保留）
```

- `--fix`：只删判定的非本领域来源，**绝不新增来源、绝不编造内容**；
  来源被清空的节点会降级为「AI 整理待查证」（其时间线若因此失去支撑也会一并清空，不做无源编造）
- `--刷新模板`：只换页面骨架，**分析结果一个字都不动**。
  升级到新版模板后（比如新增的列表视图位置记忆），用它把已有报告刷一遍就能用上新界面
- 两个参数可以一起用：`python 报告体检.py --刷新模板 --fix`

## 🆔 岗位身份（JD ID）

每个岗位有一个**稳定的结构化 ID**，它才是这个岗位的「身份」——报告文件名只是产物。

```
本科_金沙人力_数据标注质检_视频_成都_6-8K_0001
└学历 └单位      └职责        └领域 └城市 └薪资   └编号（全局递增 4 位）
```

7 段的含义（顺序固定，缺哪段就填占位符）：

> **【大白话】** 右边那列"从哪来"里出现的 `education`、`company`、`job_category` 这些，
> 是**报告内部存数据时用的英文名**（相当于表格的列名）。你不用记，只要知道
> "这几段是从分析结果里自动取的、不用你手填"就行。

| 段 | 含义 | 从哪来 |
|---|---|---|
| 1 学历 | 本科 / 硕士 / 大专… | 报告的 `education`（`统招公办本科及以上` → `本科`） |
| 2 单位 | 公司简称 | 报告的 `company`（去掉「有限公司」这类后缀与括号注释） |
| 3 职责 | 岗位类别 | 报告的 `job_category`（`数据标注/质检` → 去掉 `/`） |
| 4 领域 | 语音 / 文本 / 视频 / 图片 / 多模态 / Agent | **关键词规则**从标题与 JD 原文推 |
| 5 城市 | 成都 / 北京… | 报告的 `location`（空则从 `address` 里认城市） |
| 6 薪资 | `6-8K` | 报告的 `salary`（括号里的福利说明去掉） |
| 7 编号 | `0001` / `0002`… | 全局递增，永不重复 |

**分隔符为什么是 `_` 而不是 `-`**：薪资本身就长成 `13-26K`，用 `-` 就分不清字段边界了
（`13-26K-0001` 到底是几段？）。

### `【未知xx】` 是什么意思、怎么改

AI 有时读不到某段信息，那一段会显示成占位符，让你**一眼看出缺什么**，而不是猜一个填进去：

```
【未知学历】_【未知单位】_数据标注质检_【未知领域】_【未知城市】_13-26K_0002
```

- **`【未知xx】` 是正常的**，不是报错。缺哪段就显示哪段的占位符。
- **AI 会认错，你可以手改**：台账每张大卡片上有「**✏️ 改 ID**」，点开能看到 7 段分别是什么，
  直接在输入框里改（连 `【未知xx】` 也能改成你判断的正确值）。
- **改重了会被拒绝保存**：新 ID 与库里别的 JD 完全相同 → 后端回 **409**，界面上**当场报警**
  （「没有保存：这个 ID 已被占用……」，输入框**保持你敲的值**，不会假装保存成功）。
  （**大白话**：**409** 是"后端拒绝"的一种标准回复代号，意思是"你这次提交跟现有数据冲突了"。）
- 段数不对（必须 7 段）、有空段、带空格、带 `\ / : * ? " < > |` 这些文件名非法字符 → 同样拒绝并说明原因。
- **已有的报告文件不会改名、不会删除**（它们只是产物）；台账通过记录里的 `report` 字段找到它们。
  改 ID 会同步改掉**知识库的「来源岗位」引用**与**面试记录里的岗位引用**。

### 为什么要改身份（原来是报告文件名）

原来的岗位身份**就是报告文件名**：`20261003_语音文本评测_75分.html` —— 里面嵌了**日期与分数**。
于是「换一份简历重新分析同一份 JD」必然产生**一个新身份**，同一个岗位在系统里变成两个岗位，
知识库里那张卡就记成「**被 2 个岗位提到**」。

而「被 N 个岗位提到」是**复习优先级的乘性因子**（提得越多越是这批岗位的刚需，越该先学）——
身份一错，这个优先级就整体算错。真实数据里已实测到：**6 个概念的 `multi_jd` 全部来自同一份 JD 的两次分析**。

改成结构化 ID 之后，同一份 JD 无论分析几次、换几份简历，`jd_id` **都是同一个** ——
「同一份 JD 被算成两个岗位」**从结构上不可能**。

### 一个 JD 下可以挂多份简历分析

台账**一行 = 一个岗位（JD）**，大卡片上写的是 JD 身份串 + **「N 份分析」** + **最高分**：

- 卡片上点「**📂 展开分析**」→ 逐份列出这个 JD 下的**每一份**简历分析（简历名 / 分数 / 日期 / 「📊 打开报告 ↗」）
- 有多份分析时**默认就是展开的**（这正是你要看的「一个大块页面下挂好几份小报告」）
- 卡片底部「**＋ 用另一份简历分析**」→ 把这份 JD 的原文填回分析页，你换一份简历再点「开始分析」
- 同一份 JD 再分析一次时，工具会先提示「**这个 JD 你分析过了**」，问你要**覆盖**还是要**仍然新建一份**
  （这一步在**调模型之前**，不花额度）
- **投递状态 / 结果**是**岗位级**的（一个岗位只投一次）；**匹配打分 / 简历大纲 / 优化方向 / 面试准备**
  是**分析级**的（这些才随简历变）

## 📄 简历版本（族谱 / 母版快照 / 谁改了什么）

以前「保存简历」就是**把那个文件原地覆盖**，删简历就是 `os.remove` 永久删 —— 报告里也不记「这次用的是哪一版」。
现在每份简历是一棵**族谱**，每一次保存都是一个**有版本号的版本**，分析**钉在**它用的那一版上。

### 族谱：母简历 → 子简历

- **上传格式**：`.md` / `.txt`，以及**电子版 PDF**（电脑导出的、文字能选中复制那种）。
  PDF 由本机**纯标准库**抽出文字（不联网、不花钱、不引第三方依赖）→ 填进编辑区**由你看过、改过再点「保存」**
  （落盘仍然是 `<名字>.md`，版本库/快照/指纹一切照旧）。
  **扫描件 / 拍照转的 PDF 抽不出文字**（会明确拒绝并告诉你去 OCR）；**加密的 PDF** 也不支持（请另存为无密码版）；
  抽的是**文字流**，分栏 / 表格可能串行 —— 保存前请自己过一眼。
- **母简历** = 你点「**★ 选定继续优化**」的那一版（★ 只出现在这一行）。一份简历一个下拉项，
  **分析永远钉在当前版**（下拉给的是版本 id，写进记录与报告）
- **子简历** = 在母版基础上改动后再上传、并选了「**延续**」的那一版（`parent_id` 指向它延续的那一版，
  `rev` 是族谱内第几次修改）
- 上传时若这份简历已被选定、内容又有变化 → 弹选择：**延续**（成为子版）或**新开一份独立的**
  （独立根、`rev` 重新从 1 起）。**默认不选** —— 你不选就是「新开」，绝不自动延续

```text
示例-姓名-母版 ★（rv_0001, rev 1）
└─ 示例-姓名-母版（rv_0004, rev 2）   ← 选「延续」上传的那一版
```
（上面是**占位示例**，不是任何人的真实简历名 —— 你自己的那份会显示成你上传时的文件名。）

### 磁盘上每个族谱**最多 2 份内容文件**（这是取舍，不是 bug）

```text
resumes/<名字>.md            ← 该族谱【最新版】内容
resumes/快照/<版本id>.md      ← 【母版】快照（只在上传子版、覆盖前留一份）
```

**快照的触发条件**：只要「快照文件不存在」**或**「**按记录判断**它装的不是这一版」
（记录的 `sha256` 与快照内容不符、而盘上那份**恰好就是**这一版）**且**
「`<名字>.md` 此刻在盘上有字节」**且**「这一版的原文**不是**从来没保留过」→
覆盖前先把**盘上那份的原始字节**复制成快照（非 UTF-8 / CRLF 也**逐字节**留，
不做编码与换行转换）。**已存在就不重写** —— 母版快照一经生成即**不可变**
（这是它能当「参照原点」的前提），唯一的例外就是上面那条"**按记录判断**已过时"；
⚠️ 它的证明力**全在记录里**（记录被人工改坏时它会指错）→ 所以修正前**先把旧快照留档**
（`<版本id>.md.stale-<旧字节 sha 前 8 位>`，重名就换 `-2` / `-3` …：直接写副本、
不删除、也不冒充母版），绝不静默丢掉旧字节；**留档失败就放弃这次修正**（宁可这次不修，
也绝不把旧快照静默盖掉 —— 那是不可逆的，界面会明确报一句冲突而不是假装保存成功）。
记录里**没有** `sha256` 就**没有依据**判谁对，那时一个字节都不动。

> **这些 `.stale-*` 旁挂是"留档"，不是垃圾**：装的是"**即将被覆盖的旧快照字节**"。
> 会**累积**（同一次覆盖最多多一个；当前可达的最后一手 —— 删掉那份旧快照就真找不回了）、
> **可以手工删**（在 `data/profiles/<key>/resumes/快照/` 下）、**老数据迁移不会带走它**
> （`简历迁移.py` 只按简历文件与记录走）。只有「彻底删除」会顺带清掉**它自己那一版**的旁挂。

> **存档 ≠ 冒充**：留档留的是「**这一版的原文**」（`<名字>.md` 里那份）的字节。
> 它**与记录不符**（被程序外改过）时字节**照样留**下来 —— 那是你写的东西，覆盖掉就
> 没地方找了 —— 但**不会**说它是母版原文，界面如实提示「**内容与记录不符**」。
> **不留**只有两种：① 这一版原文**从来没保留过**；② 盘上那份**已经不是这一版**
> （文件里装的是更新的那一版 / 别人的内容）—— 那时它不是这一版的原文，存进来就是张冠李戴。

> **因此：旧版原文不保留。** 除「最新版」和「母版」以外，其它历史版本**取不回原文**，
> 只能看「**改了哪些**（AI 写的）」+「**那一版当时的分数**」。界面会**如实写明**
> 「旧版原文未保留」，**绝不**给一个空文件冒充、也绝不假装能取回。
> 这是你明确选的取舍（每族谱只留母版 + 最新），不是我们偷偷省空间。

### AI 变更说明：**模型写的**，可能漏

选「延续」时，会用**母版内容 + 这一版内容**让模型写一份 `summary` + 逐条 `changes`（改在哪一节、改了什么），
存进版本记录、**永久可查**（即使旧版原文没留）。两条纪律：

- 它是**模型写的**，界面会标「以原文为准」——**它可能漏**，没漏的也可能说得不细
- 生成失败（网络 / 额度 / 返回的不是 JSON）→ **版本照样保存**，界面**明确显示**
  「这次没能生成变更说明」+ 原因，**绝不写一个假的空说明**骗你

「新开一份独立的」**不做比对**（那本来就没有可比对的母版），一次模型都不调。

### 取回原文：三条路，各有各的说法

> **【大白话】** 为什么"打开某一份简历"要分三种说法？因为**磁盘上只保留两份内容文件**
> （母版快照 + 最新版），更早的原文**没留**。所以程序宁可**如实告诉你"没留"**，
> 也绝不给你一个空文件或旧内容冒充。
> 表里那个 `sha256` 是"**防伪码**"：内容变一个字符，这串码就完全不同 ——
> 用它来判断"文件有没有被程序之外的东西改过"。

| 你要哪一版 | 会发生什么 |
|---|---|
| **最新版** | 读 `resumes/<名字>.md`；记录里的 `sha256` 与磁盘不符 → 明确说「**内容与记录不符（可能被程序外修改过）**」，并把两个 sha 都亮出来，绝不假装一致 |
| **母版** | 读 `resumes/快照/<版本id>.md`（母版同时是最新版时读最新版文件） |
| **其它历史版** | 明确回「**旧版原文未保留**」，并给出 AI 变更说明与当时的分数（**不是空文件**） |

> ⚠️ **文件不见了 ≠ 文件是空的**：`resumes/<名字>.md` 被程序外删掉（或读不出来）时，
> 「最新版」那一行回的是**「内容与记录不符」**，**绝不**回一份空正文 ——
> 旧实现会把"被删掉"和"真的是空的"混成同一件事，界面标题照旧写「最新版原文」、正文空白。
> 只有**文件确实在、且字节上真是空的**时才是一份合法的空简历。

### 「移出列表」和「彻底删除」不是一回事

> **【大白话】** 这两个按钮最容易搞混：**"移出列表"只是把它从清单里藏起来，文件还在、随时能恢复**；
> **"彻底删除"才会真删掉那一条记录和它自己那份快照**。
> 注意最后一行：**族谱的主文件不会被删** —— 因为那是"这个简历当前长什么样"的容器。

| 动作 | 干什么 | 盘上还剩什么 |
|---|---|---|
| **移出列表**（`DELETE /api/resumes`） | 标示 `removed`：不再出现在下拉/列表，**不能再用它分析**（要延续先「恢复」） | 记录、**简历文件、母版快照、变更说明全都留着**；可「恢复」 |
| **彻底删除**（「彻底删除」按钮 + 两次确认） | 删掉**这一条版本记录** + **它自己的**那份快照文件（以及**它自己的** `.stale-*` 留档旁挂） | **`resumes/<名字>.md` 仍在盘上**（那是族谱最新版容器）；**别人的版本 / 别人的简历的文件（含别人的旁挂）一律不动** |

彻底删**撤销不了**「它曾在某次分析里被用过」这一事实 —— 历史报告里仍留着那一版的 `resume_id` 与显示名（`resume_id` = 那一版简历的编号，比如 `rv_0001`），界面会说明。

### 查重的粒度 = **(JD × 简历版本)**

| 情形 | 行为 |
|---|---|
| 同一个 JD + **换一份**简历 | **不算重复**，正常新建（这正是「几份简历比同一个岗位」的用法） |
| 同一个 JD + **同一版**简历 | 算重复 → 弹窗给两条出路：**覆盖**（沿用那条分析的 id 与报告名）/ **仍然新建**（另建一条，报告名带 `(2)`） |
| 老分析**没有版本号** | 按「版本未知」处理：**不判重复**（宁可多建，也绝不误拦把你卡死） |

> 老数据的 `resume_id` 是**推定**的：旧分析本来就没这个字段，迁移时按
> 「**简历文件的 mtime 早于这几条分析**」推断它们用的就是当前这份内容。界面会把「推定」标出来。

### 一个 JD 下多份简历的 **6 维度并排表**怎么读

展开 JD 大卡片后有一张表：**一行一份简历、一列一个维度**。

- **列怎么来的**：取该 JD 下**所有分析**用过的维度名并集，按**出现次数降序**排
  （维度名先做 NFKC 归一 + 去掉所有空白再比较 —— 真实报告里同时存在 `AI认知` 与 `AI 认知`）
- **缺的那一格**写「**该版未评这一维**」，**不是 0**（0 分是「评了、很差」，跟「没评」是两件事）
- 报告**整份读不出**逐维评分时，那一格写「报告读不出评分」，并如实说「**无法并排对比**」，不摆一张空表糊弄
- 真 0 分**照常显示 0**

### 老数据登记为版本：`简历迁移.py`

把已有的简历文件登记成 `rv_0001` 之类的版本、并给历史分析补上（**推定**的）`resume_id`：

```bash
python 简历迁移.py --试跑     # 只打印「迁移前 → 迁移后」对照表，严格只读（逐文件指纹一个字节都不变）
python 简历迁移.py --执行     # 先整目录备份，再迁移
```

- `--试跑` 先看清楚：哪份文件登记成哪个版本、它的 `at`（取文件 mtime）/ `size` / `sha256`、
  **哪几条分析会被指向它**、哪些分析**不处理**（`resume` 名对不上的一律不硬塞），以及推定依据
- `--执行` **第一步**就是整目录备份 `data/profiles/<key>/` → `data/profiles/简历迁移备份_<时间戳>/`
  （**保留不删**，你确认无误后自行删除）；失败 → 从备份恢复
- **简历文件不移动、不改名、不删除**；`knowledge.json` / `jds.json` / 报告 / 面试记录一律不碰
- 重复执行**幂等**（已登记的版本沿用，不新建、不重写）

### 把已有数据迁移过来：`身份迁移.py`

老数据里岗位身份还是报告文件名，需要迁移一次。**先看对照表、确认无误再执行**：

```bash
python 身份迁移.py --试跑     # 只打印「迁移前 → 迁移后」对照表，严格只读（一个字节都不写）
python 身份迁移.py --执行     # 先整目录备份，再迁移
```

`--试跑` 会逐条告诉你：**每个旧岗位 → 哪个 JD id、它下面归并了哪几份分析、归组依据是什么**。
判定一律**以 JD 原文的指纹为准**（两个岗位的 JD 原文高度相似就并成同一个 JD）；
**没有 JD 原文的岗位一律自成 1 个 JD**（不猜、不硬塞）。表里的 JD 数取自迁移后 `jds.json` 的
**实际条数**，所以**已经迁移过的数据再跑一次，表头会如实写「已迁移过、无新增」**（重复执行是幂等的）。

`--执行` 的纪律：

- **先整目录备份** `data/profiles/<用户>/` → `data/profiles/迁移备份_<时间戳>/`（**是 profile 的兄弟目录**，
  备份保留不删；备份里不会再套一层备份）
- **报告文件不改名、不删除**（`reports/*.html` 与 `jd/*.txt` 一个都不动）
- 改的只有：新写 `jds.json`、`jobs.json` 记录只留分析级字段 + `jd_id`、知识库与面试记录里的引用改指 JD
- 中途失败 → **从备份恢复**（连迁移新建的文件一起删掉，不留半改状态）

10. **🏁 结果与复盘**（记录拿到没拿到 offer + 你写的原因 → 到终态后让 AI 归因 → 复盘报告，闭环收口）
11. **🗑 真删除一个岗位**（只读预演逐条列清单 → 两次确认 → 先备份后删 → 任何一步失败逐字节回滚）

## 🗑 真删除一个岗位（不可恢复是它的语义）

大卡片上的「🗑 删除」。**这一步是真的删**，所以流程被刻意做长了：

| 第几步 | 发生什么 |
|---|---|
| ① 第一次确认 | 只是问你「要不要看清单」，**还没算任何东西** |
| ② **只读预演** | `GET /api/jd/purge_preview`：逐条列**将要删掉的东西** —— 每条分析（id + 简历名 + 分数）、**每个**报告文件、JD 原文与截图、会被清理的引用条数。**一个字节都不落盘** |
| ③ 第二次确认 | 清单**逐条**摆在眼前；② 区只列**真会被删**的文件，还要保留的 / 已经不在盘上的分别放在 ④⑤ 里说明 |
| ④ 先备份再删 | 备份到 `data/profiles/删除备份_<时间戳>/`，**逐字节核对 sha256 之后**才动第一个文件；删完把备份**路径**显示给你 |
| ⑤ 删了什么 | 备份路径 + 删除的文件数 + 每个「保留未删」文件的**各自原因** |

**删掉**：`jds.json` 里那条岗位记录 + `jobs.json` 里它的全部分析记录（含已合并的标记记录）
+ 那些分析的报告 HTML + 这个 JD 的原文与截图。

**只清引用、不删本体**：

| 东西 | 怎么处理 |
|---|---|
| 知识库卡片 | `from_jds` 里指向它的条目删掉，**卡片本身保留**（知识是通用的） |
| 面试记录 | `job_id` 清空，**记录本身保留** |

**绝不删别人的东西**：报告或 `jd/` 原文如果**还有别的岗位的记录在点名它**，就留在盘上，
并在清单里如实说"保留不删"（否则那条分析的报告链接会 404）。

**备份里有什么**：报告与 JD 原文按原目录存一份；事务会整份改写的三份 JSON
（`jobs.json` / `jds.json` / `knowledge.json`）与面试记录存在 `_state/` 下（按原目录结构），
另有一份 `manifest.json`（相对路径 + sha256 + 这次删的是哪个 JD）—— 手工恢复时不必猜。

> **【大白话】** 上面这段里的 `manifest.json` 就是一张**清单**，写着"备份里每个文件原本在哪儿、
> 防伪码是什么"。**手工恢复时你照着它拷回去就行**，不用猜哪个文件该放哪。
> `sha256` 是"防伪码"：内容变一个字符，这串码就完全不同 —— 用它证明"备份里的副本和原件一模一样"。

> **别把备份理解成"磁盘上还有原件"**：功能语义就是**不可恢复**（工作目录里的记录与文件都已经删了），
> 备份只是**可回滚的余地**。确认无误后可以自己删掉那个目录。

> **如果进程在删除中途被杀掉**（断电 / 强制结束），可能停在"文件删了几个、JSON 还没改"的
> 中间状态。备份里有全部原样副本（报告、原文、三份 JSON、面试记录，外加 `manifest.json`），
> 但**恢复要你手工来**（照 manifest 把文件拷回对应位置）—— 程序**不做**"启动时自动重放"。
> 自动回滚只覆盖"程序自己捕获到的失败"这一种情况。

### 什么情况下它**拒绝**删除

> **【大白话】** 表里那些数字（404 / 409）是"后端拒绝时的标准代号"：
> **404 = 没找到这个东西**，**409 = 现在这个状态不允许（比如你看到的清单已经过期了）**。
> 你不用记它们，只要知道：**下面每一种情况，界面都会用一句人话告诉你发生了什么，
> 并且绝不假装成功。**
>
> 特别注意最后一行 —— **网络断了的时候，程序不会猜**。它不知道删除到底成没成，
> 就老实说"不知道"，还顺手替你刷新台账让你自己看。这是最诚实也最有用的一种处理。

| 情形 | 行为 |
|---|---|
| 找不到这个岗位 | 明确回 404 + 一句人话，不崩 |
| 预演之后数据被改过 | **409 拒绝执行**（你确认的是**那份**清单，不是另一份），要求重新预演 |
| **会被整份重写的文件读不出来**：`jobs.json`（台账）或 `jds.json`（JD 库）手改坏了 / 存成了非 UTF-8 / 被别的程序锁住 | **拒绝删除**，并告诉你先去修文件 |
| **知识库 `knowledge.json` 读不出来** | **不阻止**删除，但明确告诉你"这次**不会**清理指向它的引用"（那个文件不会被覆盖，所以坏着也不丢东西） |
| 备份这一步失败 | 明确回「**没有删除任何东西**」—— 一个字节都没动，半截备份也会被清掉 |
| 删除中途失败 | **从备份逐字节回滚**（含已经被删掉的文件），并明确回「已回滚」 |
| 回滚**也**失败 | 用弹窗（不是 3 秒就消失的提示）把**备份目录**给你，让你手工恢复，并且**绝不说"已回滚"** |
| 预演之后面试记录变了（多了/少了一条挂在本岗位上的） | **拒绝**（要求重新预演）—— 绝不改写一份没进过备份的文件 |
| 网络中断（请求发出去了但没收到回包） | 如实说「**结果不知道**」，并**替你刷新台账**让你自己看 —— 不猜、也不让你盲目重点一次 |

> 最后一行那条值得单独说：请求可能已经在服务端跑完了（甚至已经删掉了），只是回包丢了。
> 这时说"已回滚"或"什么都没动"**都是编的**，所以界面只说"不知道"。

**为什么"读不出来"要拦住某些文件、只说明另一些**：判断标准是**这个文件会不会被这次删除整份重写**。
`jobs.json` / `jds.json` 会被重写 —— 把它们"读成空"再写回去，就是**所有岗位的分析记录 / 所有
JD 记录一次没了**（而且不可回滚），所以必须拦住；`knowledge.json` 只在真要清引用时才写，
读不出来就一个字都不写，所以只需说清楚"引用没清"。

> 台账读不出来时**整个删除功能都不可用**（不只那一个岗位）：界面会告诉你先去修文件。
> 这是**刻意**的取舍 —— 宁可拒绝删，也绝不把一个读不出来的文件覆盖成空。

## ⚡ 知识地图按岗位缓存（换简历不再重烧搜索）

> **【大白话】** 这一节讲的是"**为什么换一份简历重分析同一个岗位，快那么多、还几乎不花钱**"。
> 一句话：**"这个岗位要会哪些东西"只跟 JD 有关、跟你用哪份简历无关**，
> 所以这件事**每个岗位只值得算一次**，算过就存起来。下面那些秒数和"搜索次数"是**真实日志测出来的**。

### 为什么要缓存：它是「每次都要付」的 87%

一次分析的真实耗时与额度构成（用户真实日志）：

```
analyze.model_done      {"ms": 32209}                   ← 主分析调用
analyze.knowledge_done  {"ms": 206206, "nodes": 53}      ← 知识地图：206 秒、约 53 次搜索
analyze.success         {"ms": 236186}                   ← 一次分析总计 236 秒
```

**知识地图占了一次分析 87% 的时间与全部约 53 次搜索额度**，而它是**纯岗位级的**——
「这个岗位要会什么」只跟 JD 有关，跟你用哪份简历无关。所以它**每个岗位只值得算一次**。

### 三级回退：缓存 → 免费播种 → 真算

> **【大白话】** "三级回退"= **先试最省的办法，不行再试下一个，最后才真花钱算**。
> "播种"这个词的意思是：**你以前那份报告里本来就存着知识地图**，所以可以原样捡回来用，
> 一分钱不花 —— 就像把上次的种子拿来再种一次。

每次分析这个岗位时，按顺序试三级，命中前一级就不做后面的事：

1. **① 缓存里有**（这个岗位之前算过）→ **直接复用**，0 秒、0 次搜索
2. **② 没有缓存，但有旧报告** → **免费播种**：从这个岗位**自己**已有分析的报告里
   把那份知识地图**原样**拿来当缓存（报告里本来就存着它），0 秒、0 次搜索
3. **③ 都没有** → **真算一次**（走模型 + 搜索），算完**存进这个岗位**下次直接用

播种只会读**这个岗位自己**的报告；文件缺失 / JSON 坏了就**静默跳过、退回真算** ——
**绝不猜、绝不用别的岗位的知识地图。**
（**JSON 坏了** = 那个文件的内容被破坏、程序读不出来。这里的选择是"当没这回事、退回真算"，
而不是编一份出来。）

### 换一份简历的实际收益

| | 之前 | 现在 |
|---|---|---|
| 同一岗位换一份简历再分析 | 236 秒 / 约 53 次搜索 | **约 30 秒 / 搜索 0 次** |

省下的正好是知识地图那一块（206 秒 + 全部搜索额度），主分析调用照旧要跑
（它才是「这份简历配这个岗位几分」的答案，本来就随简历变）。
模型看到的东西**一个字都没变** —— 只是上一次算过的结果被留下来了。

> 注：约 30 秒是**主分析调用本身**的耗时（实测 `analyze.model_done` 32.2 秒 / 236 秒的同一份日志），
> 不是「缓存只有 30 秒」；缓存那一步实测就是 **0 次真算、0 次搜索**。

### 报告里那行来源标注怎么读

报告的知识地图上方会多一行小字，三种文案：

| 报告里看到 | 意思是 |
|---|---|
| `📚 知识地图：本次新算` | 这次真的调模型 + 搜索算的（会花掉约 53 次搜索额度） |
| `📚 知识地图：复用该岗位 2026-10-03 生成的那份（本次没有重新搜索）` | 直接用了这个岗位已经缓存的那份，**本次 0 次搜索** |
| `📚 知识地图：复用该岗位已有报告里的那份（本次没有重新搜索）` | 免费播种来的（从旧报告里读出来的），**本次 0 次搜索** |

- **「生成于」说的是「这份缓存生成于」**（也就是**现在复用的这份是哪个时间点算出来的**），
  **不是**「首次生成于」：你强制刷新之后，它就会变成刷新那一刻的时间。
- 只有**缓存复用**那一档会显示日期；播种来的那份显示的是「已有报告里的那份」
  （不假装知道它的确切算法时间）。
- **老报告不会自动获得这行标注**：模板改动只影响**之后**生成的报告。想让已有报告也吃上，
  跑 `python 报告体检.py --刷新模板`（只换页面骨架，**分析结果一个字都不动**、不消耗任何额度）。
- 知识地图**生成失败**时（模型/搜索炸了）**不显示这行**，而是明确写「知识地图生成失败：…」——
  「管线失败」和「真的没有知识点」绝不混在一起。

### 并发 / 双击只算一次（单飞守卫）

两个请求同时打向同一个岗位（双击「开始分析」、两个标签页、网络重试）时，
真正**真算的只有一次**（约 53 次搜索额度只烧一遍）；第二个请求**等第一个算完直接拿结果**，
不会睡死等（第一个失败时它自己再算一遍）。它在报告里按「**复用**」报 ——
因为那一行的全部意义是「**本次有没有重新搜索**」，而它确实没有重新搜索。
日志里 `analyze.knowledge_joined` 能分辨「这是等待者」和「这是缓存命中」。
（服务是多线程的，没有这道守卫的话，双击就会同时烧两遍 206 秒 + 约 53 次搜索。）

### 想强制重算：`refresh_jd_facts`

岗位信息变了、或者你想拿一份新的知识地图时，在 `/api/analyze` 的请求里带
`"refresh_jd_facts": true` → **忽略缓存重算一次**，并把「生成于」更新成这次的时间。

```bash
# 只示意请求形状：这段 JSON 就是前端点「开始分析」时发的那个 body
#   {"jd_text": "...", "resume_name": "我的简历.md", "refresh_jd_facts": true}
```

**前端暂时没有这个按钮**，只能手写 API 调用（或直接改 `jds.json` 里那条 `jd_facts`）。
不传 = 有缓存就复用，这正是本阶段的全部收益。

> ⚠️ 手写 API 时布尔值要写**真布尔** `true`，或写字符串 `"true"` / `"1"` / `"yes"`。
> 工具会按「真值口径」解析（`"false"` / `"0"` / `"no"` / 空格 / 大小写变体都算**假**）——
> 从前 `bool("false")` 是**真**，一句 `"refresh_jd_facts": "false"` 会**白烧一次 206 秒**。
> 认不出的值（`"maybe"` / `2` / `[1]`）保持原语义，语义不会悄悄翻面。

### 播种只对**迁移过**的岗位生效（如实说明）

「免费播种」读的是**这个岗位自己已有的分析报告**，而它靠 `jobs.json` 记录里的
**`jd_id`** 找（`jdid.analyses_of` 只认 `jd_id`）。所以：

- **没跑过 `python 身份迁移.py --执行` 的岗位，播种这一级不触发**（旧记录里没有 `jd_id`，
  找不到「它自己的」报告）→ 那些岗位第一次分析仍然是**真算**，算完存进缓存，
  **从此以后换简历就都是复用**了。
- 已经在用结构化 JD id 的岗位（新分析的、迁移过的）**全都吃得到播种**。

（用户当前的 `jobs.json` 是 **6 条 / 0 个 `jd_id`**、且 `jds.json` 不存在 —— 也就是说，
**今天的真实数据上播种不会触发**；三级回退里的播种那一级是在**带 `jd_id` 的隔离数据**上验收通过的，
不是拿未迁移的真实数据硬说它通过。）

## 🧠 知识库（跨岗位累积）

> **【大白话】** 这是这个工具**最值钱的那部分**：你分析过的所有岗位，里面考到的概念会
> **汇成一个本子**，一个概念**只有一张卡**（不管你从几个岗位里见过它）。
> **你标的学习进度，程序永远不会自动改。**
>
> **这一节最关键的一句话：知识库和报告是互相独立的。**
> 删掉一份报告（甚至整个岗位），**知识库里那些卡和卡里的内容一个字都不会少**，
> 只会把"这条来自哪个岗位"的记账划掉。你积累的东西是你的。

每次分析完一个岗位，报告里的知识点会**自动收进知识库**；同一个概念在不同岗位出现时**不会变成两张卡**，
而是把**来源累加**、并记下「被哪些岗位提到过」。

打开工具顶部的「🧠 知识库」：

- **列表**：按「被多少个岗位提到」排序 —— 提到越多，越是这批岗位的刚需，优先学
- **搜索 / 筛选**：按术语或定义搜，按掌握状态、分类、来源岗位筛
- **详情**：专业定义、通俗解释、前世今生时间线、**来源链接（可点开原文）**、面试会怎么问、来源岗位
- **推进掌握度**：待学习 → 学习中 → 已掌握（与报告里 `know:` 的勾是同一件事）
- **🎯 开始自测**：按优先级翻卡复习（见下面「自测复习」）
- **疑似重复**：启发式提示可能指同一概念的两个术语（如「省略恢复」/「省略识别及恢复」），**你点确认才合并**

> **你的学习进度永远不会被覆盖**：合并方向永远是「你的操作 → 知识库」，绝不会因为又分析了一个岗位
> 就把「已掌握」改回「待学习」。

已有报告里的知识可以一键收进来：知识库页右上角「**从已有报告导入**」（纯本地、不消耗任何 API 额度、可重复点）。

### 「来源岗位」这个清单是什么（以及删岗位时它怎么变）

> **【大白话】** 每张卡上有一份**记账**：**"这个概念是从哪些岗位来的"**（内部字段叫 `from_jds`，
> 每条记着岗位名和日期）。它**只是记账，不拥有内容**。
>
> **删岗位时，程序只把这份记账里指向那个岗位的几行划掉** ——
> **卡片本身、定义、通俗解释、来源链接、时间线、你标的掌握度，一个字段都不动。**
> 划完可能变成空清单，那也没关系：卡片照样能查、照样能复习，只是不再显示"来源岗位"那一栏。
>
> 这条有自动测试盯着（`test_purge_removes_records_files_and_clears_references_only`），
> 谁改坏了测试就会红。

### 🎯 自测复习（翻卡）

知识库右上角点「**🎯 开始自测**」，工具会按**优先级**一张一张地出卡，翻卡自测。

**优先级怎么算**（每次实时算，公式就是排序依据，不用猜黑箱）：

```
状态权重：待学习 = 3 · 学习中 = 2 · 已掌握 = 1
age      = min(距上次复习多少天, 30)        # 从没复习过 → 按 30 天算
被问过   = 面试里被真问过几次（asked_count，# 录了音的面试复盘会自动 +1）
score = 状态权重 × (1 + 被多少个岗位提到) × (1 + age / 7) × (1 + 被问过)
```

排序：`score` 降序；同分按术语升序（保证每次顺序一致）。一轮 20 张。

四个因子都是**乘法**，所以任何一项都不会把分数压成 0 —— 一个只被 1 个岗位提到、但还没掌握的卡，
依然排在「已掌握且刚复习过」的前面。每张卡的顶部都会写出**为什么它排前面**，
例如「待学习 · 被 2 个岗位提到 · 面试被问过 1 次 · 21 天没复习」。

**翻卡流程**：

1. 正面**只有术语**，先自己回想一遍 → 点「👀 看答案」才展开（专业定义 / 通俗解释 / 来源链接 / 来源岗位）
2. 点「✅ 答上了」或「❌ 没答上」→ **立刻落盘** → 自动递下一张
3. 顶部有进度（第 7 / 20 张）和本轮小结；答完可以「🔁 再来一轮」，随时可以「← 退出自测」

**答上 / 没答上会怎么变**：

- **答上了 → 直接变「已掌握」**（状态权重掉到最低的 1、久未复习加成归零，于是往后排）
- **没答上 → 退一档**：已掌握 → 学习中 → 待学习（待学习留在原地）。
  答错一次不该把「学习中」打回原点，但也不该留在原位骗自己
- 每次答题都会记下 `review_count`（答过几次）和 `last_reviewed_at`（上次哪天答的）
- **每答一张就落盘**，所以中途关掉程序，重开后已答的记录还在；
  服务挂掉时会明确提示「**未记录，请重试**」并且**不往下翻**（不假装记住了）

> 代价是**复用来的措辞来自你上一个岗位** —— 报告里会标出处，所以你看得见。

> **【技术口径】** 生成知识地图时先查 `data/profiles/<当前用户>/knowledge.json`
> （`kbreuse.py`）：命中的节点按"够格 / 不够格"分流；够格的整条复用并**跳过 ③ 联网搜索**
> （`knowledge.py` 的 `attach_sources` 跳过 `kb_reuse.reusable == True` 的节点），
> `got == "all"`（库里连时间线也有）的连 ④ 时间线也跳过；写回仍走既有的 `kb.absorb`
> （**不新增写路径**）。默认关闭：`knowledge.build_for_jd(reuse=None)` 就是从前的行为。

### 三种结局

| 库里有什么 | 这次怎么办 | 省下什么 |
|---|---|---|
| **一张齐活的卡**（定义 + 通俗解释 + **至少 1 条真实来源链接**） | **整条复用**（连来源链接一起）；卡里连时间线也有 → 时间线那一步也跳过 | 每个命中省 **1 次联网搜索**；有时间线的再省 **1 次模型调用** |
| **有一张卡，但不够全**（比如没有来源链接） | **照旧联网**，但结果**补进那张已有的卡**（不是新开一张） | 不省；换来的是**那张卡以后更可能复用** |
| **库里没有** | 照旧联网，存成**新卡**（与从前完全一样） | — |

> **够格的判据是"三样齐"**：`definition`（专业定义）+ `plain_explanation`（通俗解释）+
> **≥1 条真实来源链接**。**时间线不参与**够格判定（它只决定"能不能连时间线也省"）。
> 另外：**解释的文字不是省下来的** —— 专业定义与通俗解释在第一步（拆解知识点）就写好了。

### 报告里你能看到什么

顶部那行小字（在「📚 知识学习地图」上方）会多出复用统计，**原文形如**（下面每一句都是
把真模板的 `knowMetaLine()` 喂进真 node 跑出来的**逐字结果**，不是手抄的记忆；示例里的数
**互相自洽**：`55 = 5 复用 + 50 联网`、`命中 9 = 5 + 3 + 1`）：

```
📚 知识地图：本次新算；知识库：复用 5 条（含时间线 2 条） · 命中 9 条（其中 3 条不够格，已联网补全、1 条与其它节点指向同一张卡（内容为本次生成）） · 本次联网 50 条
```

**怎么读这句话**（口径与后端 `stats` 逐字对应）：

- `复用 5 条` = **整条**拿了库里那份内容的节点数（`reusable`）；`含时间线 2 条` = 库里连时间线
  也有的那些（`timeline_reused`）—— 它们连写时间线那次模型调用也省了。
- `命中 9 条` = **拿到了"命中"这件事的节点总数**（`matched`）＝ `复用 + 不够格 + 与其它节点指向同一张卡`
  三类之和（`reusable + enriched + aligned_only`）。所以它**一定 ≥ 复用条数**。
- `3 条不够格，已联网补全` = 命中了但库里那份不全，这次照旧联网（`enriched`）。
  ⚠️ **只有"没有任何一条被搜索上限截断"时才敢说"已联网补全"** —— 被上限拦下那批一条都没搜，
  对它们说"补全了"就是假话（所以有上限截断时这句会退成光秃秃的「3 条不够格」，见下面第二例）。
- `1 条与其它节点指向同一张卡（内容为本次生成）` = `aligned_only`：它和**另一条**节点共用库里同一张卡，
  这次只把名字对齐、内容仍是本次生成的（详见下面「三种结局」与「诚实局限」）。
- `本次联网 50 条` = **真的发起过几次搜索**（`searched`），受 `max_searches` 上限约束 ——
  它**不是**"节点总数 − 复用数"（旧口径会把被上限截断的也算成"搜过"，是**多报**）。
- 一条都没联网时多一句：`… · 本次联网 0 条（本次没有联网搜索）`
- 有节点被上限截断时，末尾多一句（同一句里同时给出被截断的条数）——**同一批数、只把上限调小**：
  `📚 知识地图：本次新算；知识库：复用 5 条（含时间线 2 条） · 命中 9 条（其中 3 条不够格、1 条与其它节点指向同一张卡（内容为本次生成）） · 本次联网 35 条（另有 15 条超出本次搜索上限，本次没有联网）`
  被截断的节点在报告卡片上也有戳（`search_skipped=capped`），卡片那行**不会**对它说"仍全部联网补齐"。
- **上限截断这条不是编的**：用户 2026-10-14 那次真算的日志就是
  `total 55 / searched 40 / skipped_by_cap 15`（`knowledge.sources_done`），
  拿这三个真值喂真模板跑出来的逐字结果是：
  `📚 知识地图：本次新算；知识库：复用 0 条 · 命中 0 条 · 本次联网 40 条（另有 15 条超出本次搜索上限，本次没有联网）`。
- **老报告**（快照里没有 `kb_reuse` 这个字段）**一个字都不渲染**，绝不编一段统计出来。

每张卡下面会多一行小字。下面四行同样是**真模板逐字渲染的结果**（`kReuseLine()`）：

```
🔁 来源与时间线来自本地知识库（同名命中 · 最早来自 《语音/文本评测》· 2026-10-03）；本次没有重新搜索
🔁 来源链接来自本地知识库（AI 判定命中）；本次没有重新搜索；JD 里写作「ASR」；时间线为本次补算，已写回知识库
⚠ 命中了本地知识库里的卡片（最早来自 《语音/文本评测》· 2026-10-03），但库里内容不够格（缺 来源链接），同名命中，本次仍全部联网搜索补齐
⚠ 与另一条节点指向本地知识库里的同一张卡（最早来自 《语音/文本评测》· 2026-10-03），这条的内容是本次生成的（AI 判定命中），本次仍全部联网搜索补齐；JD 里写作「ASR」
```

- 括号里的 `同名命中` / `别名命中` / `括号缩写命中` / **`简写命中`** / `AI 判定命中` 告诉你
  "**是怎么认出来的**"。其中 **`简写命中`** 是"JD 里写的是**去括号的头名**、库里那张卡带了括号"
  这一条线（`词错率` ↔ 库里的 `词错率（WER）`）—— 它**不是**括号缩写命中（节点的名字里一个括号都没有）。
- `JD 里写作「ASR」` 在**三条支路都会渲染**（够格复用 / 命中但不够格 / 只对齐身份），
  判据只有一条：**这个名字真的被改成了库里的规范名**（字面不同）。名字本来就一样时不渲染。
- **不够格那行绝不说内容"来自知识库"** —— 内容确实是这次联网搜来的。
- **只对齐身份那行也不说"不够格"** —— 那张卡可能内容齐全，只是已经归另一条节点了；
  它说的是"与另一条节点指向同一张卡、内容为本次生成"。

### 三种"如实说明"（不是错误，是它不肯骗你）

| 你看到的 | 什么意思 |
|---|---|
| `…；本次知识地图来自缓存（cache），本次没有重跑「库优先」`（或 `来自种子数据（seeded:<报告id>）`） | 这次知识地图是从**该岗位的缓存 / 旧报告**直接拿的，**"先查库"这一步根本没跑** → 所以**不说"复用了 0 条"**（那会让你以为查过库、只是没查到） |
| `…；⚠ 本次没能查本地知识库：<原因>；已全部改用联网搜索` | 知识库**读不出来**（手改坏 / 存成非 UTF-8 / 被别的程序锁住）。**分析照常做完**，只是这次没查库 |
| `⚠ 命中了本地知识库里的卡片…但库里内容不够格…本次仍全部联网搜索补齐` | 命中了，但**不够格** → **不说成"来自知识库"** |

> ⚠️ 上表第一行的括号里**只会出现 `cache` 或 `seeded:<报告id>`**（生产只有这三个取值：
> `cache` / `seeded:<报告id>` / `computed`，见 `jdfacts.py` 的 `SOURCE_CACHE` / `SEEDED_PREFIX` /
> `SOURCE_COMPUTED`）。
> **旧写法记的是 `来自缓存（cached:…）` —— 那个值生产不可达**（保留在这里供对照）：
> 模板里虽然留了一条 `cached:` 开头的兜底分支（预防性代码，防止以后有人往快照里塞这种值），
> 但 `knowMetaLine()` 只认 `cache` / `seeded:` / `computed` 三种 —— 真塞一个 `cached:` 开头的
> `source`，它会走到末尾的 `else` → **整行（连复用统计一起）都不渲染**。
> 也就是说：写 `cached:…` 既是"生产不会出现的值"、又是"出现时这一行根本不会显示"。

### 知识库会自己长大，但**够格的复用不会覆盖你的内容**（真正会变的只有下面那几处，逐条写清）

每次分析都会把结果**写回**知识库（`kb.absorb`）：

- 库里已经有那张卡 → **复用与补全都落回原来那张卡**，**不新建重复卡**
  （靠"**身份对齐**"：命中后先把这条的名字对齐成库里的规范名，再写回）。
  **三条支路都做这件事**：够格复用 / 命中但不够格 / 以及「这张卡已经归另一条节点了，
  这条只对齐身份、内容仍是本次生成的」那条 —— **最后那条支路**正是"不新建重复卡"在
  "一卡一条"场景下依然成立的原因（不说清楚这一点，那句话就是空话）。
- **够格复用的写回几乎不额外改你的卡**：内容是**原样复制**过去的，合并规则是
  "更长者胜 / 来源取并集 / 时间线只取更长的 / 定义与通俗解释**严格更长**才换" → 那张卡只会：
  ① 多记一条"这个岗位也用到过"（`from_jds`）；② 更新 `last_seen`；
  ③ 再按 `kb` **自己**的两条合并规则跟着变 —— `layer` 取 **min**（这次 JD 把同一个概念归到
  更基础的层时会被拉低）、`related` / `interview_questions` 取**并集**（并进本次为这个 JD
  头脑风暴出来的那几条）。
  ⚠️ ③ **不是复用造成的**：同一个概念不复用、直接当新节点写回，这两条规则一样会生效
  （`kb._merge_into`）。但**它是真的会变** —— 所以旧文档里那句"除 `from_jds` 与 `last_seen`
  之外**逐字节不变**"**说过头了**，现已按实际口径改写成上面这句（真库里 **101 / 145 张卡是
  `layer` 1**，这条 min 规则经常踩到）。另有一条强不变量测试盯着**这三类之外**的字段
  （它的夹具刻意取等值 `layer`、空 `related`，这个前提写在测试自己的 docstring 里）。
- **绝不动你的学习进度**：`state`（待学习 / 学习中 / 已掌握）、复习次数、面试关联，
  程序**一个字都不改**。

### 删报告**不会**删知识库（这是两份独立的文件）

> **【大白话】** 你当初最担心的就是"删报告会不会把攒下来的知识一起带走"。**不会。**
> 因为**报告与知识库是两份互不相干的文件**：报告是 `reports/*.html` 里的**快照**，
> 知识库是 `knowledge.json`。删岗位时程序**只**把卡片里那份"来源岗位"记账（`from_jds`）
> 中指向它的几行**划掉** —— **卡片、定义、通俗解释、来源链接、时间线、你自己标的掌握度，
> 一个字段都不动**。划完那份记账可能变成空的，那也没关系：卡片照样能查、能复习，
> 只是不再显示"来源岗位"那一栏。

同样的说明在「🧠 知识库（跨岗位累积）」那一节也写着（那里是它的出处），
并且有自动测试（`test_purge_removes_records_files_and_clears_references_only`）盯着 —— 谁改坏了就会红。

### 想重置 / 想备份

知识库就是**一个 JSON 文件**：`data/profiles/<当前用户>/knowledge.json`
（当前只有一个用户目录：`default`）。备份它 = 备份你积累的全部知识；
想从零开始，把它改名或删掉即可（**删了就没了，它没有版本历史**）。
程序自己在读到坏文件时会先把坏文件**改名备份**，绝不静默当空库覆盖。

### 诚实局限（一条都不藏）

- **命中率取决于概念集重叠度，别指望每次都省**：用你自己的两次分析实测（下面写了**怎么算出来的**，
  可以照着复查），第二次要的 **53** 个知识点里，**只有 6 个**能靠"名字完全一样"从库里认出来
  （**11%**）—— 因为那两次的**概念集几乎不重叠**。
  **同一个领域反复投递时会高得多**（第一次攒下的那批概念正好都能用上）。
  > **怎么算的（可复查）**：拿第二次那份报告快照
  > `data/profiles/default/reports/20261008_语音文本评测_72分.html` 里的 **53 个节点**，
  > 与"**那次分析之前库里已有的卡**"按 `kb.normalize_id` 比精确同名。
  > "当时已有"的取法：把现在的 `knowledge.json`（145 张卡）里 `from_jds` 带 `2026-10-08`
  > 那一条的卡排除掉（那些是**这次**才吸收进去的）→ 剩 **99** 张；命中的 6 个是
  > 语音识别 / 语音合成 / 上下文窗口 / 指代消解 / 检索增强生成 / 根因分析。
  > 旧写法记的是 **5/53（9%）**，并且把两次说成"语音/文本评测 vs 标注管理/多模态" ——
  > 那句**对不上任何一份报告**（它引的那条 JD `本科_泰盈科技集团_标注管理_多模态_成都_12-20K_0001`
  > 自己的知识地图是 **55** 个节点，见 `jds.json` 的 `jd_facts.knowledge`；53 是 20261008 那份的）。
  > 两份报告的 `job_title` 都写着「语音/文本评测」，但第一份全是 ASR 评测专有概念、
  > 第二份是大模型 / 标注 / 质检那一类，所以低命中率的结论不变。
- **整条复用的措辞来自另一个岗位**（这是你选的"整条用库里那份"），
  报告里会标出处，但那不等于为这个岗位量身的。
- **模型判定那一步可能认错**（名字对不上时让 AI 判一次"这俩是不是同一个概念"）。
  缓解有两条、**都在报告里看得见**：标题用库里的规范名并括注 JD 原本的写法
  （`风险识别` 被认成 `语音识别` 时，报告会写「语音识别（JD 里写作 风险识别）」）、
  以及那行"来自本地知识库"。**不承诺零误配**，只保证**看得见**。
- **认错的代价是"库里那张卡的内容被换掉"，而且不可逆**（这是最值得知道的一条，如实写）：
  判定认错 + 命中那张卡**不够格**时，`kb.absorb` 的合并规则是"**更长者胜**" ——
  库里那张卡的**定义 / 通俗解释**会被**另一个概念的文本**替换掉（谁更长用谁），
  `timeline` 可能被**整段**替换、`sources` 取并集。**卡片没有版本历史，所以退不回去。**
  报告里能看见的只有「JD 里写作 XX」这一句提示，**没有"要不要合"的确认门槛**
  （这是"宁可不要重复卡"换来的取舍）。**你的进度字段（`state` 等）是安全的**，不受影响。
- **报告里可能看到两条同名节点**（一条是库里那份、一条是本次生成的并标着"只对齐身份"）。
  这是**设计上接受**的：写回时它们会并进同一张卡，但观感上你会觉得像重复。
- **"被哪些岗位提到"这个数字会因复用而变大**（`from_jds` 只增不减），
  而它是自测复习的**加权因子** → 反复出现的概念会被排到复习队列前面。这是**刻意的**。
- **老报告不会获得这些新标注**（报告是快照）：要看得**重新分析**；
  `python 报告体检.py --刷新模板` **也不行** —— 它只换页面骨架，不重算知识地图。
- **知识库没有版本历史**，写回不可逆（缓解：只会变长 / 补全，且不碰进度字段；
  但"判定认错 + 更长者胜"那一条**确实**会把内容换掉，见上面那条）。

## 🎤 面试复盘（真实录音 → 本机转写 → AI 复盘）

面完一场，把**录音（或视频、或文字稿）**丢进去，工具在本机转成带时间戳的文字，
再让模型写一份复盘报告：整场总评 / 被问到的问题 / 考察方向占比 / 答得怎么样（含更好的答法）/
新出现的术语 / 面试官专业度 / 二面准备 / **完整转写原文**。**录音不出本机**（本地模型转写）。

**怎么用**

1. 「📋 岗位台账」里找到那家公司 → 点该行的「**🎤 面试复盘**」
2. 面板里选文件上传（`wav / mp3 / m4a / aac / flac / ogg / opus / mp4 / mov / mkv / webm / avi`，
   也可以直接传文字稿 `txt / md`）→ 等
3. 转写与分析都在**后台**跑，面板可以关掉去干别的；回来后点那行的「**📊 打开复盘报告 ↗**」，
   报告就是 `data/profiles/<当前用户>/reports/iv_<面试记录id>.html`（**可打印 / 导出 PDF**）

**依赖：本机要有 vidkit（`video-link-extractor`）**

转写不是这个工具自己做的 —— 本项目**零第三方依赖**，不把 faster-whisper 引进来。
它是以**子进程**调用本机已有的 `video-link-extractor` 的 `.venv`：

- 需要它的 `.venv/Scripts/python.exe`（Windows）与 `models/medium` 模型都已就绪
- 默认**自动探测同级目录**（`..\video-link-extractor`）
- 装在别处，就在 `data/profiles/<当前用户>/config.json` 里加一行
  `"vidkit_dir": "D:\\你的路径\\video-link-extractor"`
- 缺失时**上传当场给出可操作的报错**：目录找不到 → 说「去设置里填目录」；
  目录在但没有 `.venv` → 说「先按它的 README 建 `.venv`」。
  **绝不静默给你一份 0 字转写**

**为什么会慢（所以必须是后台任务）**

CPU 上转写大致是**音频时长的 0.9 倍**（vidkit 自己的实测：11 分 23 秒音频 → 613 秒）。
也就是 **30 分钟的面试录音要等约 27 分钟**；带上 AI 领域词库后本机复测更慢
（60 秒片段 86～116 秒、11.7 秒片段 12～28 秒，视机器负载）。所以：

- 上传后**立刻返回**（不会让浏览器等到超时），状态**落盘**在 `interviews/<id>/status.json`
- **关掉程序再开**：界面会说「上次被中断，可重试」——不会永远转圈
- 重试**从失败的那一步继续**：已经转写完的**不会重转一遍**（不白烧那 27 分钟）
- 失败**一律保留录音**，只写 error 状态，**绝不删你的文件**

**为什么没有百分比（转写阶段）**

上传阶段那个百分比是**真的**（浏览器实测的上传字节数）；但**转写内部不报进度**
（faster-whisper 没有进度回调），所以**不编一个假百分比**：
界面显示的是**真实已运行时长**；只有上传时 ffprobe 探到了音频时长，才多给一句「预计 ≈ N 分钟」。
探不到（没装 ffprobe / 不是媒体文件）就只显示已经跑了多久。

**为什么不做说话人分离**

本地 faster-whisper **不做 diarization**，分不出「谁说的」。转写只有文字 + 时间戳，
谁问谁答是模型**从内容推断**的（所以报告里的「问题 / 回答」是推断，不是声纹结论）。
要做严格的说话人区分得另上一个 diarization 模型，那是另一个依赖，本项目不引。

**为什么新词要手动入库**

报告里会列出「你可能没听懂的新术语」。它们**不会自动进知识库** —— 一次面试就能灌进来十几个词，
里面混着模型猜的、没价值的词，复习队列会被灌爆。所以每个新词旁边有「**➕ 加入知识库**」：

- 点了才建卡，状态是「**待学习**」并进自测队列；不点就什么都不发生
- 用 `file://` 双击打开报告时按钮会**明确禁用并说明**（连不上工具就入不了库），**不假装加成功**

**答砸的知识点会自动降级**

复盘里判「答砸了 / 没答上」的知识点会回写知识库：`asked_count + 1`（= 面试官真问过）、
`last_outcome = 没答上`，原本的「**已掌握**」**降级成「学习中」**；
被问过的概念在自测队列里**排得更靠前**（见下面「自测复习」的优先级公式）。

> **「被问过」是确定性匹配出来的**（知识库里的术语是否出现在转写里），**不是让模型去记**：
> 可测、零额度，也不会因为模型漏读而漏记。

## 🏁 结果与复盘（有没有拿到 offer → 为什么 → 复盘报告）

求职闭环的**最后一步**：前面几步都做完之后，在这里收口 —— **这个岗位最后是什么结果？
没拿到是为什么？** —— 并把结论反哺回知识库。

**怎么用**

1. 「📋 岗位台账」里找到那个岗位 → 点该行的「**🏁 结果**」
2. 面板里选**结果状态**（复用台账已有的词表：未投递 / 已投 / 待回复 / 面试中 / 已拒 / Offer / 放弃），
   再把**你自己知道的原因**写进「原因」框（比如「HC 冻结」「薪资没谈拢」「三面挂在一句话上」）
   → 点「💾 保存结果」
3. 只有走到**终态（已拒 / Offer / 放弃）**，「🔍 让 AI 归因」才可点。点它 → AI 结合**这份 JD**、
   **该岗位的面试复盘**（有的话）与**你写的原因**，推出一份**复盘报告**
4. 报告里「要补的知识点」旁边有「**➕ 加入知识库**」——点了才进复习队列（状态「待学习」）

报告存到 `data/profiles/<当前用户>/reports/oc_<岗位id>.html`（`oc_` 前缀与面试复盘的 `iv_` 区分开），
**可打印 / 导出 PDF**。结构是：你写的原因 → 降级说明（仅当没有面试记录）→ AI 总评 →
可能原因（每条带依据、置信度、可控/不可控）→ 不可控因素 → 具体改进动作 → 要补的知识点 →
下次怎么调 → 原始依据（面试复盘要点 + JD 要点）。

**为什么要先记录结果才能归因**

没到终态（以及**从没记过结果**）时，「🔍 让 AI 归因」是**禁用**的，并写明「还没有结果」。
放行的话，AI 会给一个**结果未知**的岗位写「你为什么没拿到 offer」——**没有依据却言之凿凿**，
而你会把它当成事实读进去。拦住的体验反而正确：看到「还没有结果」→ 去记录结果 → 再复盘，
这正好就是「**先记结果，再复盘**」的顺序。（判据是状态落在终态词表里；
状态**缺失或非法同样拦**，不设例外。）

**为什么你写的原因和 AI 的推断分开显示**

「你说的」和「机器猜的」是**两份数据、分开存**（`outcome_reason` / `outcome_ai`）：
报告里**先原样显示你写的原因**，AI 的推断一律**明确标注**、另起一段。

混成一段的代价是：你再也分不清哪句是自己的判断、哪句是模型编的，最后会
**把自己的判断误当成机器的结论**。而且 **AI 归因永远覆盖不了你写的字** ——
重复归因只更新「AI 那一块」（你的原因在点保存时就已落盘，**归因失败也不会丢**）。

**为什么没有依据的原因会被丢掉**

归因要求每条原因都带**依据**（引用某个被问到的题 / 某个答砸的点 / JD 里的某条要求）。
**没有依据的条目直接丢弃** —— 宁可这一节空着、并如实说「模型没有给出带依据的原因，可以重试」，
也不填「可能沟通能力不足」这种放之四海皆准的废话。
同理，「**可控 / 不可控**」没标出来就单列成「**未判断**」，**绝不默认成「可控」**——
那等于在没有依据的情况下宣称「这事你能控制」。

**没有面试记录时会明确降级**

只记录过结果、从没上传过面试记录时，归因**照样能用**，但报告里会单列一段「降级说明」：
归因只基于 JD 与你写的原因，**AI 没有看到任何面试过程**，涉及「面试表现」的推断都是从 JD 反推的。
**不假装它看过你的面试。**

**归因里的知识点要手动入库**

和面试复盘同一个取舍：报告只**列出**要补的知识点，**不会自动建卡** ——
一次归因就能带出十几个词，里面混着模型猜的、没价值的词，自动入库会把复习队列灌爆。
点「**➕ 加入知识库**」才建卡，状态「**待学习**」并进自测队列。
用 `file://` 双击打开报告时按钮会明确禁用并说明（连不上工具就入不了库），**不假装加成功**。

| 词 | 一句话 |
|---|---|
| **JD** | 招聘网站上那份岗位描述 |
| **台账 / `jobs.json`** | 你每次分析的记录，存在你电脑上的一个文件里 |
| **JD 库 / `jds.json`** | 比台账多存"岗位的稳定编号"和"这个岗位已算过的知识地图" |
| **知识库 / `knowledge.json`** | **你跨岗位积累下来的概念本子**，一个概念一张卡 |
| **知识库优先（库优先）** | 生成知识地图时**先翻你自己的知识库**：够格的整条拿来用（**跳过这次联网**），不够格的照旧联网并补进那张卡 |
| **复用 / 命中 / 不够格** | 复用 = 整条用库里那份（跳过联网）；命中 = 库里已经有这张卡（**含"内容不够格"与"只对齐身份"两种**，所以报告里"命中 N 条"总是不小于"复用 M 条"）；不够格 = 命中了但缺定义 / 通俗解释 / 来源链接，仍要联网 |
| **只对齐身份（`aligned_only`）** | 这张卡**已经归另一条节点**了（一卡一条），这条只把名字改成库里的规范名、内容仍是本次生成的 —— 这样写回才会并进同一张卡、不新建重复卡 |
| **`from_jds`（来源岗位 / 引用）** | 卡片上那份"这个概念从哪些岗位来的"**记账**；清掉它**不会**让卡片消失 |
| **快照** | 某一刻原样复制下来的内容。报告里存的就是当时的快照，所以**老报告不会随知识库更新而变** |
| **缓存 / 播种** | 算过一次就存起来下次直接用 / 从你自己旧报告里把上次的结果捡回来用 |
| **搜索额度** | 联网搜索（Tavily / 博查）的配额，用完要花钱 |
| **API 额度** | 调用 AI 模型的次数，同样要花钱 |
| **防伪码（`sha256`）** | 内容变一个字符，这串码就完全不同 —— 用来证明"文件真的没被动过" |
| **404 / 409** | 后端拒绝时的代号：404 = 没找到；409 = 现在这状态不允许（有冲突） |
| **逐字节 / 回滚 / 备份** | 一模一样到每个字节 / 删失败时从备份还原 / 动手前先复制一份放着 |
| **`<当前用户>` / profile** | 用户目录。现在只有一个（`default`），所以路径里看到的都是它 |
